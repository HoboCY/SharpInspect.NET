## 准入边界

`ILocalAdministratorRecovery` 接受恢复码及个人凭据，不接受 UI 提供的安全状态。
物理控制台由现有 Windows WTS/本机会话观测确认；Windows 管理员身份不授权应用恢复。
Runtime 提供内部排他门，会话服务提供只在身份写事务内持有的短同步 lease。
正在认证的 provider、迟到 provider、会话审计持久化及待完成退出均属于冲突。

当前生产 Runtime 的 Handshake 为 Unknown、Recovery 为 Required，Stop 终态仅为 LocallyDisarmed。
因此默认恢复入口保持 `SafetyStopUnverified` 拒绝；没有公开的 safety bool、测试开关或可替代该事实的宿主 provider。
真实 PLC 停线与恢复核实能力尚未交付，后续必须由 Runtime 自身的真实操作事实接入内部门。
本票内部受控正向场景只证明开发流程，不能作为现场安全停线或工位合格证据。

## 恢复与轮换事务

恢复要求已消费 bootstrap、没有可用管理员、持有当前工位的有效恢复码，且真实会话服务没有登录、退出审计或迟到认证冲突。
重绑现有账号保留 PrincipalId、用户名和个人名称；凭据与授权 revision 更新。
成功事务同时消费使用的码、撤销旧包其余码、写入恢复审计、将 Kit 标为 RotationRequired。
恢复者尚未通过个人认证，因此恢复事件 Actor 为空，重绑账号只作为 Target；恢复不会自动登录。

恢复后必须用新密码正常登录，再以当前个人会话和一次密码复核轮换 Recovery Kit。
轮换事务生成 CustodyConfirmationRequired 状态；只有提交该包的调用能获得一次性秘密对象。
保管确认使用该包中的一条码作为证明，原子消费后才将剩余码计入身份准入条件。
锁屏、账号切换或页面关闭丢弃未领取及迟到的秘密；持有已交付的包可在重启和重新登录后继续确认。
包丢失时可重新认证后创建另一个包，旧操作 ID 不会重新交付原包。

schema 6 / identity format 4 使用永久成功操作表，拒绝尝试不占用成功操作 ID。
成功记录、审计事件、密封的操作计数与链根、身份状态在同一 SQLite 事务提交；可重算的行 hash 本身不作为信任依据。
schema 5 需要受治理迁移，不能隐式升级或采纳现有身份库。

## 页面与独立消费者

维护页面与遮蔽层提供恢复入口。遮蔽层先结束当前个人会话，恢复界面不会解锁生产页面或自动登录。
密码与恢复码通过 PasswordBox 输入；日志和错误状态使用封闭原因码。
恢复包仅绑定签发时的个人与 Session，领取和复制都检查当前真实会话。
