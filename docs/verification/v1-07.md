## 真实边界

`Freeze` 只冻结 hash-bound 文档，不接受 UI 传入“通过”。显式注册的开发 scenario 只收到预约身份、
冻结前提/刺激及只读输入，不获得账本 writer 或生产 Runtime 权威。内置规则只执行 `exact-text-v1` +
`public-test-data-v1`，预期与观测使用严格 UTF-8 和 ordinal 比较；未知规则及未实现的治理检查方法为 Blocked。
当前可执行环境规则只有 `observed-environment`，绑定实际 OS、.NET、架构、逻辑处理器数、corelib 字节及开发调用契约。

每项产品与 context 文件均在明确根目录内按实际字节复核；独立 candidate 子目录的全文件清单也进入指纹，
新增未列为单独组件的文件同样使旧候选失配。场景 descriptor 由设施派生实际类型、程序集身份/hash 和声明配置，
不能仅自报 TestId/hash；场景、设施及已加载应用程序集均匹配 context。运行前后各复核一次，拒绝路径逃逸、
reparse 与指纹失配。SourceRevision 仍是调用方的源版本声明，本票不核验 Git 服务器历史或证明目录包含完整源代码。
该进程内设施信任已冻结的测试代码，
不承诺阻止恶意代码自修改或执行后恢复文件的攻击；完整受控发布设施不属于本票。
已加载的非平台程序集包括应用目录之外的真实依赖，均按身份、位置 hash 和文件 hash 冻结。
用户定义的动态程序集不能进入该设施；CLR 的匿名 DynamicMethod 容器按运行时实际对象身份识别，
归于平台基础设施以支持 JSON/反射，不采用可伪造的程序集名称白名单。

账本有自有 application_id/schema，不能接管生产追溯库；原始 artifact 内联 SQLite，与相关预约或终态
同一次 append 事务。签名 head 在数据库外原子更新，绑定 ledger identity、schema、keyId、sequence 与链头。
DB 先提交但 head 更新失败时不回滚或重写已提交证据，保持阻塞。查询不修复、迁移或补写证据。
本票没有清理、覆盖、恢复签名根或重新锚定接口。

Profile 明确每个声明适用不变量、适用性、层级、方法、环境、前提、刺激、预期、证据及接受规则。
开发 Profile 的映射只对应本票范围，不冒充完整 V1 Profile。正式 Claim 的执行入口仍拒绝，
所有记录固定 `DevelopmentOnly`，任何聚合的 `CanIssueQualification` 始终 false；所选开发检查通过也只返回
`IncompleteDevelopmentEvidence`，同候选历史有效失败则为 `CandidateFailed`。
