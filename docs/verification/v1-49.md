# V1-49：启动维护中的 SQLite 前向迁移

关联 GitHub #50；父规格 D11、D12、T14；ADR-0075、0076、0079、0080。
本票的完整开发验证与两轮独立复核已通过；实际执行结果见文末。

## 实现范围

公开入口为 `SqliteStartupMaintenance.OpenAsync`。调用者提供目标
`ProductionStoreOptions` 和 `StoreStartupMaintenanceOptions`，取得独占维护会话后
逐次调用 `AdvanceAsync`，最后异步释放会话。维护入口不创建生产 Runtime、
身份写入服务、后台审计投递器或生产武装任务。

当前内置迁移目录只有 Schema **32 → 33**：源库已经启用 Draft、身份、审计、
生产准入及 ProductionArming；目标仅增加 RecipeLifecycle，其余配置必须保持一致。
所有已存在功能的实际配置、完整审计和业务重放由生产存储的同一实现核验。
未知路径、更新版本、必需外部审计锚点策略，以及无法证实闭合的旧恢复工作均拒绝，
不自动改变配置、降级、恢复或跳过证据。

会话与生产写入方争用同一个数据库 `.lock` 文件，并在整个维护生命周期持有它。
部署入口必须为维护和生产提供同一已合格的数据库路径，并保证旧、新程序不会
同时写入；路径别名或绕过该锁的写入方不在本迁移协议支持范围内。
源库中的生产检查、生产准入、相机设置、相机恢复、相机网络维护、标定、
预览、手动检测、两类资格验证、配方激活、配方切换握手、武装尝试及 PLC
通信恢复必须具有各自真实的终结证据。状态检查使用完整账本，而非第一页或
最近一个聚合状态。成像设置与身份修改的授权及效果本来就同事务提交。

`DecisionCommitted + ProtocolFault` 是配方切换账本定义的不可再追加终态，
不会伪造 Response、ACK 或 Reset。已结束的武装尝试可能仍保留可选状态投递预算，
这不被当作开放尝试。尚未关闭的旧纪元 PLC 通信恢复仍拒绝迁移；当前没有
跨纪元补写完成事实的迁移捷径。`CycleRetired` 是内存边界，不伪造持久记录。

## 备份、提交与恢复

维护阶段依次进行源库核验、TRUNCATE checkpoint、一致性备份创建与验证、
事务开启、旧约束表记录暂存、规范表重建、生命周期配置和签名激活、目标核验、
提交意图刷盘、数据库提交及冷重开确认。大型 checkpoint 只在该独占维护会话执行。
暂存表位于已合格的源库事务内，不向环境 TEMP 目录拼装证据。
数据库大小预算不代替磁盘空间预留；一致性备份、事务暂存表和 WAL 需要额外空间。

备份由 SQLite Backup API 分页产生，不分别复制 DB 与 WAL。验证内容包括
实际 Schema、配置、完整审计、逻辑指纹、文件字节数与 SHA-256。
配置可选择完整 `integrity_check` 或 `quick_check`；默认完整检查。
WAL、FULL synchronous、foreign_keys=ON、wal_autocheckpoint=0 均实际读回。
源程序版本和 SHA-256 来自维护主机提供的本地程序集；只读元数据，不加载执行。
该路径是来源声明，不被当作数据库生成者的独立证明。

外部日志包含操作 ID、源/目标 Schema 和程序身份、源/目标逻辑指纹、审计头、
备份证据及阶段。日志采用版本化、定长帧边界、规范 JSON、哈希链接和强制刷盘。
永久标记先于日志创建并刷盘；缺失配对文件、残缺帧或错误绑定都留在维护状态，
不截断或重新建立一份看似干净的日志。日志的哈希是操作完整性检查，不是
抵抗具有完整目录管理权限者的独立安全边界。

唯一数据库写事务保存旧记录的 rowid、列序、类型与全部值。迁移只改变明确的
约束与新增表，原事实前缀和审计头必须保持一致。提交意图必须先于 COMMIT
持久化，并绑定已验证备份和确切目标代次。重启时只接受相同源代次，或具有
持久提交意图且完全匹配的目标代次；其他状态拒绝。已记录完成后允许正常
追加事实，启动核验仍检查迁移审计前缀及整个实际审计链。

维护状态的 `Ready` 始终为 false；成功结果为
`SchemaMigratedStartupReconciliationRequired`。它不代替正常启动对账、武装、
外部锚点准入或真实 PLC Ready 回读。库迁移不是整套工位恢复备份。

旧程序不认识新增外部日志。提交前进程退出仍留下原 Schema32 时，旧程序可能
重新打开该原代次；后续迁移会检测任何源指纹变化并拒绝。迁移后的 Schema33
由实际旧程序的版本拒绝阻止写入。部署启动器、物理停机交接、程序槽位切换、
完整备份集与人工恢复属于后续 T65/T66，不能从本票的软件证据推定。

## 复现

运行 `tools/Test-Ticket49.ps1 -ArtifactRoot <绝对证据目录>
-Schema32PackageFeed <保留的Schema32包目录>`。包目录须含真实旧版 Runtime 与
Abstractions NuGet 包；不能给新旧消费者传同一包目录。也可设置进程环境变量
`SHARPINSPECT_SCHEMA32_PACKAGE_FEED`。T49 之后的完整验证仍执行该迁移兼容性探针。
所有探针在隔离目录中运行，通过公开 API 创建源库，并输出每阶段进程日志、
持久状态、备份证据及新旧程序集/包哈希。

开发执行时将 TEMP/TMP 指向 F 盘，并在结束后恢复进程环境。
本地签名密钥、隔离软件工位与模拟事件不构成生产权限或正式合格结论。
真实断电、目标设备断电写入特性、物理 PLC/相机、外部锚点迁移、完整部署切换
及整套恢复演练为 **NotRun / 未准入**。
