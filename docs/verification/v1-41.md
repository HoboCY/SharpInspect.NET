## 适用边界

显式启用 `ModbusCommunicationBinding` 的隔离 loopback Profile 使用 T40 的同一
`InspectionCycleCoordinator`、采集、算法、Core COMMIT 和 Ack 状态机。
新通信 owner 只管理传输代次、心跳、同步和恢复，不能创建 Run、重算结果或发出生产 Ready。
没有通信 binding 的旧构造函数保持 T40 行为及原 Profile hash；它不产生 T41 健康证据。

所有时间值由不可变版本化 `PlcCommunicationPolicy` 显式提供：轮询、单次 I/O 截止时间、
双方心跳周期和陈旧期限、重连间隔和次数、同步稳定窗口与每次同步的最大时长。
所有活性和稳定窗口使用 Stopwatch；UTC 时间仅用于审计显示。

原控制块 6 + 6 个寄存器保持不变。新 PLC 通信块为 12 个寄存器：uint32 ControllerHeartbeat、
完整 16 字节 RuntimeEpoch 回显、uint32 RuntimeHeartbeat 回显。新 Runtime 通信块为 10 个
寄存器：完整 RuntimeEpoch 和变化的 RuntimeHeartbeat，通过一个 FC16 原子写入。
uint32 使用网络字节序；Guid 使用 .NET `ToByteArray()` 的原始 16 字节序，PLC 必须逐字节回显。
所有通信、控制及结果报文区间必须互不重叠。

首次读取只建立基线；ControllerHeartbeat 必须实际变化，PLC 回显必须属于本连接实际发送的
RuntimeEpoch/Heartbeat 元组且向前变化，双方才形成活性证据。单次读写成功或 TCP 建连不够。
同步还要求非零 ControllerEpoch 稳定、Trigger/ResultAck 持续归零达到窗口；
审计持久化之后重新观察一个完整稳定窗口，不能将审计等待期间的盲区计入稳定证据。
政策的同步时长必须至少容纳两段稳定窗口；实际 Profile 还需为初始活性、I/O 和审计留出预算。
当前版本的全部 PLC-owned 握手输入就是这两个布尔值；增加握手输入时必须一并扩展同步谓词。
独立 watchdog 在周期写入或其他采样暂停时仍能撤销旧许可。

断线、心跳陈旧或运行中换代先同步撤销准入、取消旧周期，再记录审计和尝试恢复。
只有旧 observer、采集/执行与传输 I/O 实际退休后才创建新的通信连接。
新连接严格使用原数值端点、端口、Unit ID 和寄存器 binding；连接成功不会重置尝试预算。
开始发送新鲜心跳前会撤销远端残留 Ready，保持原 Busy/ResultValid 和结果报文。
未解决的运行/交付禁止重新同步成可接纳状态；耗尽后保持锁存并等待受治理恢复。
空闲清洁连接可以重新同步新 ControllerEpoch，但不会自动 Arm 或续接旧资格会话。

Core COMMIT 前的通信故障固定 Cancelled/Unknown 和稳定原因；COMMIT 后保留原运行及 payload，
仅追加未解决交付/故障事实。重连后的旧 Ack 不能完成已终止的原周期。
独立通信账本绑定 PLC Adapter System Principal、进程 RuntimeEpoch、端点/Profile/Policy hash、
连接代次、恢复尝试以及存在时的原 session/run/key。它不能修改 T40 的结果账本。
`SynchronizationWindowObserved` 仅记录已经观察到的稳定窗口，不代表此刻健康，
也不能解除历史恢复状态。恢复状态按端点、RuntimeEpoch 和 RecoveryCycleId 隔离，
只有匹配的 `RecoveryCompleted` 能解除通信恢复；查询按指定高水位计算，UTC 回拨不改变单调排序。
