## 适用边界

本票使用明确声明的 loopback 开发设施：Runtime 是真实 Modbus TCP 客户端，设施是实际 TCP 服务端。
`ModbusQualificationProfile` 显式绑定数值回环地址、端口、Unit ID、两个控制寄存器块、场景、
已批准 Trace Storage Policy 的精确版本及 snapshot hash、轮询、传输和确认超时。
Plan 的 ProfileHash 及瞬态控制器 EndpointBindingHash 必须与该 Profile 一致。
设施观察仍按 T37 的 session/lease nonce/runtime epoch、配置读回及五类隔离目的地验证。
设施不向 Runtime 直接发出内部状态转换，也不拥有资格 Run ID 的构造权限。

Controller 块为六个连续 holding registers：Trigger、ResultAck、ControllerEpoch 高/低字、
CycleSequence 高/低字；两个 uint 使用网络字节序和高字在前。
Runtime 块为六个独占写寄存器：QualificationReady、Busy、ResultValid、CycleFault、
ProtocolViolation、ProductionReady。最后一位始终写零，全局 Station Ready 也保持 false。
两个块不能重叠，完整 PLC 结果合同内的任何字段也不能覆盖它们。
启动时若 Runtime 块存在旧 Busy/Valid/fault/permit，不以初始化写覆盖它，保持恢复阻塞。

传输使用 FC03、FC06 和 FC16；FC06 仅能写 Runtime 自有布尔寄存器。
每个连接串行核对 MBAP transaction/protocol/unit/length、function、byte count 和写入回显，
精确读取拆分的响应，FC16 每个请求最多 123 个寄存器。报文段保持编码器给出的最终 PDU 字节。
请求或响应不确定后关闭并封锁该连接，不自动重连或重放写入。
协议依据：[Modbus Application Protocol V1.1b3](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf)
及 [Modbus TCP/IP Implementation Guide V1.0b](https://www.modbus.org/file/secure/messagingimplementationguide.pdf)。

## 周期与持久屏障

`InspectionCycleCoordinator` 是共用的采集、实际算法、编码、持久提交和发布序列。
旧 T37 设施入口也调用此序列，结果输出移到完整运行记录 COMMIT 之后。
新 Modbus 入口选择 Runtime 产生的 `QualificationRunId`、独立非生产记录和隔离通道。
接纳前固定外部 epoch/sequence 和政策快照，接纳记录先于相机采集；不创建生产 Inspection ID。

schema26 Qualification Cycle ledger 与 T37 运行记录在同一个 SQLite writer 事务内追加，
冻结精确政策、Evidence=None 和空外部路由。只有绑定最终不可变 run/payload 的实际提交回执
能进入发布。观察、计算结果或设施返回成功都不是持久回执。后来的政策版本不重解释旧周期。
核心结果与交付事件分开：提交不等于 PLC 已消费。PublicationPrepared 先于第一段写入，
所有段写完后才清 Busy 并升 ResultValid；真实 Ack 高后清 ResultValid，真实 Ack 低后结束握手。
整个四阶段内不修改 payload，重复观察不追加第二个运行或重编码结果。
CoreCommitted 后的运行记录和 payload 不可撤回或改写。退出、取消、响应丢失及提交返回超时
只追加故障或交付未解决事实，不能将已提交结果改写成 Cancelled 或删除其 payload。
若提交回执超过硬截止时间，即使独立冷读能看到 CoreCommitted，当前周期也禁止发布。

独立采样在计算、事务等待和 Ack 等待期间持续进行。忙、重复、零身份或非允许请求变为拒绝事实，
不进入下一周期队列。已拒绝的高 Trigger 不会因恢复空闲而被接纳；其外部 key 也不重放。
拒绝事实队列有明确容量，溢出封锁并报告；告警映射不会取消当前已接纳运行。
ControllerEpoch 在活跃周期内改变会取消当前工作并保留稳定 controller-change 原因；
同代次的新 CycleSequence 依照忙时拒绝规则处理，不冒充控制器换代。

正常算法 Error/Timeout 且产生了合法 AlgorithmExecutionOutcome 时，
保存 Unknown payload 并经过相同提交和 Ack。算法自行抛出取消异常依既有执行合同归类为 Error，
同样走 Unknown 握手；Runtime 主动中止则保留取消事实并封锁周期。
没有有效算法结果时不伪造 Success result archive。
核心事务失败或超过硬 TraceCommitTimeout 会阻止普通结果发布；迟到 COMMIT 只能留下不可变核心
事实及后继 fault，不能重新打开输出门。Ack 超时保持当前锁存值和 payload，不生成假 Ack。
任何不确定状态写都会永久封锁该输出 owner，后续 partial update 不会重放或擅自清零。

未解决周期、故障或中断的 Modbus 会话保持 RecoveryBlocked。退休等待实际相机、算法、
观察和网络任务；不经过 T37 普通 controller restore / ReleaseIsolation 路径解除锁存。
冷启动同样不补发、不重算、不恢复控制器或释放隔离。告警确认不解除该事实屏障。
