关联 GitHub #54，父规格 D10、D12、D14，以及 ADR-0072、0073、0074、0079、0103。
本轮基线为 `4302f5c`。下列证据属于开发验证，不构成正式发行或真实工位资格。

## 不变量和实现边界

Transient 与 UnknownOutcome 使用原 Delivery ID、原始字节有界重试；Permanent 停止自动尝试。
Required 的永久阻塞立即禁止新的生产触发，不等待数量、年龄或字节积压超限。
BestEffort 失败保持 `ProductionImpact=None`；已有 Core、PLC 结果及冻结报文不被处置操作改写。

人工恢复在同一权威写事务中重查个人权限、会话、精确目标、原因、新鲜单次 Step-Up
及当前状态版本，再追加授权和恢复记录。若已开始 A 次，本次授权 N 次，则新上限为 A+N，
不恢复前一窗口的未用次数；原预算加所有授权总数仍不超过 32。
容量检查同时预留所有未来尝试、结果、收据和其他未完成义务；拒绝不改变交付、不消耗授权。

更正交付拥有新 ID、显式新字节和原交付关联。原字节、历史及终态保留，不能把失败直接标为送达。
本入口只更正原路由／Payload Contract 内的内容，不能借此切换部署路由、Content Type 或契约版本。
新的外部 schema 必须由独立的路由／契约版本及相应部署治理引入；原 Required 待办仍需保留兼容处理器。

schema 37 启动按历史路由身份／版本、Payload Contract 及已注册适配器契约精确解析。
缺处理器时追加持久 HandlerBlocked，保留原始字节，不虚构新发送尝试；旧活动尝试先记录 Unknown。
恢复处理器本身不解除阻塞，仍需受授权恢复。schema 36 保留旧兼容语义，不能据此声称已具备 37 的持久处置。

schema 37 是显式扩展，必须经 36→37 Startup Maintenance 迁移启用。
迁移重建必要 CHECK 约束，保留旧行、rowid、NULL、哈希和原始字节；恢复激活沿用原签名检查点间隔。
先前任意受支持的 32／33／34／35→36 操作可接续到 37，原日志保持追加式关联。
