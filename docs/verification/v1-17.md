## 设计与证据约束

`ICameraSetupRuntime` 是 Runtime 的非生产调试入口，WPF 仅通过 Abstractions 调用。
Provider 注册、逻辑角色绑定和工艺配置分别建模；发现候选不会自动选择或打开设备。
普通 `StationStateSnapshot` 仅投影角色、绑定修订和健康状态，不公开设备身份。
配置成功呈现 Open / Applied / Stopped，失败呈现 Closed / Unknown / Stopped，
两者均不授予 Active Recipe 或生产 Ready。

Provider 调用的前台等待有时限；忽略取消或迟到的调用继续由 Runtime 的有界资源所有者持有，
完成后才清理，不能发布迟到成功或提前复用未释放资源。设备健康读取和关闭也受该生命周期约束。
关闭/释放无法确认完成时，本次操作失败并撤销有效配置，不能据此打开替代设备或宣称物理释放成功。
这使故障隔离和调用返回有界；进程内框架无法强制终止永不返回的第三方原生调用。

相机配置存储须显式启用 schema 10。绑定修订使用 CAS，配置受理与终态通过
操作身份、授权事实和追加审计关联；重启不重放硬件操作，也不将持久化的历史成功当作当前设备已配置。
既有 schema 1/2/7/8/9 不自动升级，配置不匹配时拒绝，保留原数据库字节。
schema 10 可与可选的算法结果归档、Recipe Draft 和报警历史共存。

Provider Extension 固定 Provider 四项身份、扩展契约及版本和配置内容 hash，并明确不可移植。
普通 Recipe Draft 保留既有格式 1 的规范序列化和内容 hash；带扩展依赖的草稿使用格式 2，
通用编辑器修改工艺参数时保留该依赖，未知扩展在相机配置入口拒绝。

## 聚焦回归记录

- `V117-Q01` 初次运行的四个组合失败：测试误把 schema 初始化产生的
  `PolicyActivated` 报警历史视为不应存在。断言改为验证该条初始化事实、空报警实例及只读字节不变；
  修正后的 Q01–Q03 共 8 个用例通过，原失败 TRX 保留。
- 真实消费者第一次绑定被 `AuditAuthorizationPayloadInvalid` 拒绝：相机变更说明的自由文本
  被错误填入身份审计的封闭管理原因字段。自由文本现由类型化相机事件保存，身份审计遵守原封闭契约。
- 第二轮消费者在绑定受理后达到 100 秒进程期限。授权预留跨 `await` 持有线程绑定的会话租约，
  导致异线程释放失败并阻塞后续会话访问。修复将会话租约的取得、提交和释放放入同一同步写入回调；
  异步操作仅持有授权预留元数据。失败数据库保留了绑定受理事实，未伪造完成。
- 后续消费者暴露 `IdentityCommandCorrelationMismatch`：相机写入工作项未关联操作的命令身份。

  同时持久化失败终态并清空 Effective 与差异，不以设备关闭代替审计成功。
