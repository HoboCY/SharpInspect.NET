关联 GitHub #56；依据 D09–D12 与 ADR-0065、0068、0070、0071、0073、0076、0078、0079。
基线为 `a4147aeffd757690a65dd8c42d96953837a2f8d4`。本文件描述本地开发验证，不代表正式发行或真实工位资格。

## 配置及生产边界

`ProductionStoreOptions.StorageRetention` 显式启用 schema 39，要求已有 Trace Storage Policy 和 T54 对账能力。
配置同时冻结版本化保留执行策略、批准依据、允许删除的类别、每轮条数／字节／时间／间隔、
每个主体的最大删除尝试次数，以及容量观察、物理操作与启动超时。没有隐含的生产清理策略。
运行时仍要求已发布且与部署匹配的 Trace Storage Policy；缺少策略、观察未知、过期、时钟回退、
不完整盘点或缺少锁存 `TraceStorageCapacityBlocked` 告警映射时，不能接收新的生产 Trigger。

核心库、WAL、stage／final／隔离根分别显示可观察字节、数量和卷空间。
预留取固定字节与卷百分比的较大值；恰好等于预留可用，少一个字节阻塞。
WAL、数量、字节及积压年龄采用达到上限即阻塞的边界。
完整、可恢复且在预算内的 PNG／Required Outbox 积压不等同于完整性故障。
观察不足时保留 Unknown／Unavailable；达到盘点上限显示不完整下界，不能填造完整统计。
容量恢复不会自动清除已锁存告警，仍需既有受权复核和复位流程。

schema 39 的 WAL 写入门读取已批准策略；旧 profile 保持原协议。
新 Admission 必须通过写入器的最终复核，已接受的 Core、图片与 Outbox 工作保留其原有限额内的结算权。
容量门不会取消当前算法或重新解释已接受周期的完成契约。

留存配置还必须显式给出 `TraceStorageRecoveryBudget`：控制写入的 WAL 准入门槛、
控制事实总配额和 checkpoint 规划余量，全部进入配置及部署指纹。
普通 WAL 门达到上限后，仅既有密码认证／会话操作、精确绑定
`ManageProductionPolicy` + `PublishTraceStoragePolicy` 的 Step-Up 和策略发布事务可申请该预算。
原权限、密码、会话、目标载荷、版本 CAS 和完整审计校验仍然生效；其他治理命令不因此获准。
配额累计留存启用后所有 `IdentityEvent` 和 `TraceStoragePolicyEvent`，包括平时认证，
重启和发布策略均不补充。配额或控制准入门槛耗尽时保持不可用，不声称支持任意磁盘耗尽后的自救。
控制 WAL 数值是事务开始前的准入水位，不是物理硬上限；单次事务可能使实际 WAL 超过该值。
新策略的普通 WAL 门必须小于控制门槛，checkpoint 字节与帧预算必须容纳发布前实测 WAL 加显式规划余量，
帧数依据实际 SQLite 页大小计算。该规划不预测 SQLite 的写放大，也不取代启动时的实际预算检查。
恢复依次经过受权修订策略、停止并等待物理所有者退休、重新启动维护和原有恢复复核；
策略发布自身不会执行 checkpoint、抹除历史失败或自动解除生产故障。

## 保留与删除证据

保留义务从原始已验证 manifest／成功 finalization／原始策略及 T54 隔离完成事件派生，
不使用文件 mtime、当前策略或新建时间代替原始起算事件。无法证明起算的旧隔离内容继续保护。
已生成义务的起算、原期限、来源哈希和策略哈希不可变；后续只允许延长或有序登记／释放 Hold。
人工操作要求 `DeleteEvidence` 权限、当前会话、精确命令载荷绑定的新鲜 Step-Up、观察到的修订及处置原因。
身份事实、命令结果和保留事件在同一事务提交；拒绝不消费授权，且不得挪用待结算的删除事件预留。

只允许显式配置的到期权威图片、隔离证据或孤儿 stage 类别进入删除候选。
未结束周期、未释放 stage、未成功的原始 Required Outbox、Hold、未到期和受保护事实均排除。
补交成功不能替代原 Required 交付义务。Core、原审计事实、manifest 和 Outbox 历史不被删除。
每轮按到期顺序受条数／字节／运行时间限制；跨重启仍遵守持久间隔和最大失败尝试数。
回拨时钟不能启动新的删除，但不能阻止已发生物理操作的结果结算。

在写事务外打开并验证精确文件和祖先目录，持有同一文件身份、长度、原始哈希和根绑定，
先持久化 DeleteIntent，再通过同一已验证句柄删除，最后追加 Tombstone 或失败／未知事实。
拒绝重解析点、多硬链接、身份或内容变化；超时不能释放尚未退休的物理操作所有权。
Windows 使用带 POSIX 语义的句柄删除，使共享读取句柄存在时仍能观察到名称实际移除；
不支持时失败保留，不退回可能产生虚假成功的旧删除语义。
参见 [Microsoft FILE_DISPOSITION_INFORMATION_EX](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddk/ns-ntddk-_file_disposition_information_ex)。
Tombstone 字节是逻辑删除量；实际空闲空间由独立容量观察证明，不据此推算磁盘已回收。
中断后缺少可信物理结果时记录 Unknown 并阻塞恢复，不能因文件消失补造删除成功。
T54 核对仅在精确 Tombstone 与实际缺失一致时接受已退役文件；巡检记录 Deferred，不声称重新验证了已删除像素。

## 停产维护及运维界面

生产接线中的删除只发生在启动维护屏障内，之后后台轮次仅补建可证明的保留义务。
checkpoint 使用同一数据库写入器及进程锁，发生在初始化完成、完整性监视器和交付 worker 放行之前。
批准策略的 checkpoint 预算限制帧数／字节／时间／间隔；开始与结果均进入中央签名审计链。
Busy、预算不足、未知结果可查询并阻塞相应容量门；重启遇到未结算开始记录时写 Unknown，不推断成功或立即重试。
完成事实本身会再次增长 WAL，容量查询仍测量当前文件。没有在线 VACUUM 或第二个无界写入者。
Runtime 退出的逻辑期限不等于物理结束；旧物理 worker 真正退休前不会释放库锁供新的启动维护使用。
38→39 迁移仍通过现有 Startup Maintenance，绑定原库、原配置、独立旧应用与备份，不能直接跳过已要求的父迁移。

WPF 维护页显示容量、WAL／checkpoint、策略、保留主体及冻结上界的分页历史，提供 Hold、释放和延长。
离页、锁屏、注销、销毁或验证身份期间修改内容会清除选择与敏感输入；迟到响应不得恢复历史或提交旧请求。
不可用或畸形响应不会成为可操作的证据；分页上界不得扩大。
页面不保存密码、直接删除文件或启动 checkpoint。SampleHost 通过可选服务接入；未配置时明确显示未配置。
保留查询及页面同时显示恢复预算与已累计控制事实数；计数来自同一已验证审计快照。
预检根据实际 checkpoint 结果和图片积压报告已通过、缺证、策略不匹配或失败，
旧 profile 的未实现项继续保留原状态。
