## 实现边界

`PlcResultContract` 明确声明寄存器地址、容量、数值表示、字节序、字序、单位与有理数仿射
转换、舍入方式、溢出拒绝、状态与原因代码表、非成功数据及可选值缺席表示。每个 Schema
measurement 必须明确映射或排除；可选值使用经安全性证明的哨兵，或独立有效性字段和明确
缺席数据。没有宿主字节序、默认零值、钳制或截断规则。

固定的 `PlcResultContractBinder` 对整个声明值域证明可编码性，验证完整代码表、单位、
地址不重叠与容量。不同 Schema 分支互斥，可以复用地址。无法证明完整值域的转换拒绝绑定；
`Exact` 不以端点可表示代替区间内部证明。数值转换使用精确有理数与 IEEE 位分解；所有舍入
和端序由契约决定。只读绑定是可编码性证明，不表示配方已经发布或授权改变工位配置。

`PlcResultPayloadEncoder` 重新核对实际执行的配方、算法、Schema 与结构化结果，先构造全部
字段，再返回不可变快照。状态、产品判定和原因独立编码；任何错误返回
`PlcResultEncodingFault`，没有半包。控制器 Epoch / Cycle Sequence 为 UInt32，Result Sequence
回显 Cycle Sequence。分段记录只包含声明地址，地址空隙不补写。线内容哈希绑定有序地址与
字节；整体哈希额外绑定契约、Schema、配方、执行身份和验证版本。

既有 T12 公共执行入口仍拒绝 Production。公开样例通过真实 Manual 单帧执行调用
`EncodePreview`，得到独立的 `PlcResultPayloadPreview` 类型，绑定 Manual 来源和明确标注的
样例 Epoch / Sequence，没有 InspectionId，不能作为生产快照传入未来发布接口。
预览与生产快照使用不同哈希域。生产 `Encode` 仍要求 Production outcome；内部友元测试
单独构造 Production 夹具核对相同线内容，未把 Manual 结果改名为 Production，也未开放
生产执行准入。完整 Core Record、生产发布准入与真实 PLC 握手由后续 ticket 实现。

`ProductionStoreOptions.PlcResultContracts` 明确选择 schema 17，依赖真实身份、草稿与发布
存储。旧数据库不自动升级。`ChangePlcResultContractCommand` 绑定新契约、预期当前版本和
变更原因；Runtime 在 Ready=false、Disarmed、无执行及待确认投递时持有命令租约，确认真实
人员权限与新鲜 Step-Up。服务从准确发布历史推导所有受影响 Recipe，逐个重新绑定，写事务
重新比较发布高水位和当前契约。成功同时记录不可变版本、完整验证与配方绑定、命令结果、
身份授权及中央审计链；失败不替换当前版本。历史 Recipe 发布记录及内容哈希不变。

三种契约冷查询和命令追踪入口均要求 Drafts / Releases / LocalIdentity / Audit 配置。
schema 17 即使发布高水位为零，也要求物理发布账本存在。历史重放按每个契约的审计序号
重算准确高水位与相邻旧/新 Schema 的受影响集合；后来的发布不会使旧契约失效。
契约查询在同一只读快照捕获已验证 checkpoint，并在返回结果前完成政策要求的外部锚核验。
