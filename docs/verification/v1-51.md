# V1-51：从耐久暂存恢复并提交无损 PNG

关联 GitHub #52；父规格 D09、T11、T12；ADR-0066、0067、0068、0070。
本票实现 PNG 最终化、耐久重试和只读证据页。完整开发验证、实际包消费者、
旧 ABI 消费者和独立审查已通过；此结果不构成正式发行或真实工位资格。

## 配置和执行边界

部署显式配置 `ProductionStoreOptions.ImageFinalization`，它引用确切的
`ProductionImageEvidenceStoreOptions` 和 `ProductionImageFinalizationRootOptions`。
已有 stage 与 final 根目录必须为独立的本地固定 NTFS 目录，禁止云同步、
reparse 路径和目录重叠。根路径及容量参与不可变配置哈希。
未启用此选项的旧配置继续使用原有 schema 和政策指纹。

Runtime 在存储初始化后启动一个无头工作器；恢复不要求相机、PLC 或 UI 会话。
部署指纹同时绑定最终化配置及固定执行参数：一个工作器、一个物理文件槽位、
容量为一的合并唤醒信号、最多 8 MiB 编解码工作缓冲、30 秒文件操作期限、
5 分钟启动核验期限、5 秒物理退役等待和 1 秒空闲轮询。
8 MiB 是编解码缓冲预算，不能解释为 Runtime 或 SQLite 查询的总内存上限。
查询、生命周期条目、单条字节、总字节、重试次数、根目录文件数及页大小
另有配置上限，超出则拒绝；不通过无限内存队列保存工作。

启动按不可变 Core 位置分页验证已引用的 stage 与 final，再核对有界目录清单。
已成功且 stage 已删除的工作仍验证 final。未引用文件保留并要求对账，
不会因为文件名看似有效就取得权威身份。正常扫描以固定水位和递增游标处理，
早期耗尽预算的工作不能占满第一页并遮蔽后续工作。

## 像素、文件提交与生命周期

输入来自 T50 持久 stage 和 Manifest。规范哈希仍覆盖 `SIPIXEL1` 信封及紧密像素行，
不包含行 padding 或 PNG 编码参数。Mono8 保存为灰度 8 位；Mono16 保留
10/12/16 位右对齐数值并转换为 PNG 的 16 位网络字节序；Bgr24 转为 PNG RGB。
解码核验恢复同一规范表示并比较 SHA-256。权威 PNG 不缩放、不叠加、不有损，
本票不生成缩略图或带叠加的派生图。

一次工作依次执行：

1. SQLite 追加绑定工作、尝试 ID、编号和确切临时名称的 `AttemptStarted`。
2. 保护已核验的 stage，以 CreateNew 写入唯一临时 PNG，调用 `Flush(true)`，
   完整解码校验尺寸、格式、有效位、规范像素哈希和 PNG 结构。
3. 在 final 根内不覆盖地原子重命名，重新打开最终文件并检查实际句柄路径。
4. 文件组件签发不可伪造、单次消费的内部凭证。只读保护句柄保持到 SQLite
   返回实际事务结果；只有绑定完全匹配且运行围栏仍有效才追加 `Succeeded`。
5. durable Success 后再次保护并校验 final，通过已验证的文件句柄删除 stage，
   再追加独立 `StageReleased`。已删除而尚未记录释放的窗口可幂等恢复。

最终名称由 Manifest ID 唯一确定；临时名称还包含已持久记录的 Attempt ID。
恢复只接纳已有持久尝试绑定的 final，并再次完整解码，不能另造第二权威图片。
已知尝试的临时文件仅在规范 stage 仍完整时清理。损坏 final 不允许删除 stage。
已发布 Core、Manifest 和初始工作事实保持不可变；新事实仅追加到最终化生命周期。

语义取消或超时关闭凭证发布，实际 I/O 仍持有物理槽位和句柄直到退出。
停机有界返回不能视为线程已经终止，也不会启动第二编码器。
进程退出留下的 active attempt 追加中断失败；存在已核验 final 时可完成同一尝试，
否则受耐久重试时刻和次数约束。调用者伪造未来记录时间不能绕过等待。
临时编码失败保留 stage 并追加失败；成功后的清理失败保持 Succeeded，单独重试清理。

## 生产准入和完整性

完整且在项目数、规范字节、年龄预算以内的 Pending 工作不撤销 Arm。
达到任一上限时，由既有单一报警维护任务记录 `ImageEvidenceBacklog`，
其部署映射必须指定 source `Runtime.ImageEvidence` 和 `BlockNewTriggers`。
启用最终化要求同时配置该规则及下述完整性规则；缺少任一规则均拒绝生产准入。
心跳亦检查年龄，不依赖新的审计事件。
政策决定是否锁存；非锁存规则在积压回到预算内后记录来源恢复和清除。
已接受周期仍可提交并发布，生产准入门明确显示 `ProductionImageBacklogLimitExceeded`。
最终化四类操作审计不会被误当成生产配置变化。积压投影通过审计水位合并
尚未出现在查询快照中的 Core，避免新义务丢失或重复计数；成功图片移出运行积压，
历史数据库容量仍保留并计入存储限制。

缺失或损坏的已引用证据以及身份矛盾进入 `EvidenceIntegrityFault`，
要求真实报警映射为 Latched、BlockNewTriggers，并包含 RecoveryComplete 和
NoActiveExecution 复位条件。Runtime 立即关闭准入，SQL 亦拒绝带完整性冲突的义务。
替换文件字节或普通重试不能解除故障；内部 `IntegrityRecovery=true` 也被拒绝。
临时 WAL/队列提交拒绝和 I/O 等待不会被伪装为已证实的像素损坏，工作器
从已验证的耐久状态再次恢复。无法恢复的存储配置和孤儿清单检查仍关闭准入，
但使用实际故障或对账原因，不为无引用文件制造 `EvidenceIntegrityFault`。
自动尝试耗尽后保存 Failed 及原始失败原因，`RetryEligible=false`；有效的既存
final 仍可按已有尝试重新验证，次数上限不能使已有权威候选无法完成。
有授权证据的人工处置、历史巡检及保留删除属于后续票，本票不模拟这些授权。

## Schema 35 与证据页

显式启用最终化才启用 schema 35。新增不可变配置、追加事件及可重建的工作状态投影，
并绑定中央审计。查询重放事件并验证投影、Core、Manifest 和完整配置。
每个开放义务为成功及 stage 释放预留事件，每个 active attempt 另预留终结失败。

schema 34 库必须通过独占 `SqliteStartupMaintenance` 的 34→35 操作迁移。
迁移不重写旧事实，继续保留 32→33、33→34 及其已完成操作的哈希链接。
错误根配置、未知 schema、被篡改激活或缺失表集合均拒绝。

WPF 图片证据页只读显示持久状态、尝试、失败、规范哈希、最终描述和事件历史。
分页固定 Core 水位；筛选变化、退出授权展示或关闭页面会丢弃迟到查询结果。
无服务或不可用查询明确显示不可用，不伪造成功。旧 ShellWindow 构造器不变，
通过新增附加入口接入，未配置最终化的 SampleHost 仍可启动。
