# V1-22 可复用 Camera Provider 契约验证

关联工单：[Issue #23](https://github.com/HoboCY/SharpInspect.NET/issues/23)。

## 交付边界

`SharpInspect.NET.Cameras.Conformance` 仅依赖公共 Abstractions 与 Runtime。
它不引用 WPF、Virtual、Hikrobot 或可选网络维护实现。Provider 维护者在自己的验证宿主中
实现 `ICameraConformanceFixtureFactory`，并将 `CameraConformanceSuite.Scenarios` 注册到 T07。
本票的无 UI 示例 `SharpInspect.CameraConformance.Probe` 独立引用 Virtual，提供固定数据和时钟。

本票产生 DevelopmentOnly、Provider 层的 Test Execution Record。
回调栈、回调预算和原生分配需要独立观察设施；当前三个必需场景保持 **Blocked**。
真实 SDK、型号、接口、Runtime、OS 和触发模式的 Hardware Qualification 为 **NotRun**。
任何局部通过或 Virtual 重放均不能使厂商组合成为 officially supported，也不授予生产 Ready。

## 固定输入与公共观察

fixture 声明冻结 Provider 四元身份、Stable Device Identity、1–10 个完整请求配置、逐配置的首帧与不同挑战帧规范像素 SHA-256、
池容量、种子、帧延迟和公开数据描述。输入包括一个 fixture artifact 和一个 case catalog，均由套件计算真实字节哈希。
示例使用固定版本／种子、2×2 图像、Mono8、Mono16 10/12/16 位及 Bgr24，包含软件和硬件触发。
规范帧摘要覆盖所有有效行字节，不把行尾 padding 当像素；Mono16 包含奇数源步长输入。
取消／额外帧／Lease 场景的后续帧使用不同像素，分别验证迟到帧隔离与持有缓冲区未被覆盖。
池耗尽后若公共健康表明设备已关闭，先完成退役，再从同一 Provider 重开原设备、完整配置并验证采集。
恢复事件必须属于同一 epoch／cycle，序号连续，包含断线、启动、尝试与完成；事件溢出或缺失不能通过。

fixture 只承认外部刺激是否送达。Virtual 的公开脉冲与时钟 API 代表外部测试装置；
健康状态、配置读回、Busy、相关 ID、协议事件和 Lease 都由 suite 通过公共接口自行观察。
场景不读取厂商私有字段，不反射 Provider，不使用 Virtual 的实现诊断计数。

每个场景创建独立 fixture；释放 Lease、Runtime 所有者、设备／Provider 后等待 `CleanupCompletion`。
执行超时不等于物理资源已经释放。Runtime 新增公开 `RetireAsync()`，返回包含 `SafeToReplace` 的真实退役完成观察；
它不受调用方面向响应的 `DisposeAsync` 等待上限替代。Stop／Dispose 失败仍是不可替换，Provider 不会被提前销毁。
T07 与 suite 均保留实际执行占用，直到观察任务及清理真正结束。
恢复场景由 `CameraRecoveryService` 管理原身份重开与完整配置，fixture 仍保持最终清理责任。

## 可选扩展与证据绑定

扩展使用独立 `V122-X-*` Test ID，不能占用核心 ID。fixture 通过冻结的 `OptionalExtensions`
声明支持范围；声明了扩展却没有测试注册，suite 构造直接拒绝。
已声明的扩展必须执行，缺观察设施则 Blocked。未声明的注册项只有在冻结 Profile 引用排除证据哈希、
Context 与请求包含同一 `applicability-proof`，且内容精确绑定当前 candidate 和 Test ID 时，T07 才记 NotApplicable。
多个排除项各用含自身证明的独立 Context；最终 Profile 仍包含核心和所有注册扩展。
该显式开发声明与证明不代替真实设备能力证据。

| 对象 | 绑定位置 |
| --- | --- |
| 实际 Provider／框架程序集、消费依赖 JSON 与锁文件、构建配置 | Candidate 及完整目录清单 |
| suite、fixture、所有实际加载的应用程序集 | Context Harnesses 的实际文件哈希 |
| 稳定场景定义、suite 版本、当前声明 | Context Scenarios；T07 在执行前后校验 |
| fixture 与 case catalog 原始字节 | Context Datasets 与每次 reservation 输入 |
| 种子、限额、像素计算规则与实际环境 | Context 对应字段 |
| 每次执行身份、候选／上下文／Profile 哈希、ADR 不变量、原始输出 | 不可覆盖 reservation 与 Test Execution Record |

报告记录全部场景的实际结果及范围限制。`query` 从独立进程打开只读 ledger，核对报告与记录、
输入／输出字节哈希和映射，并确认 ledger／密钥文件没有改变。失败记录不能通过重试覆盖。
