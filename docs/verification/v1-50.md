## 政策与部署配置

Recipe 的 `EvidenceCapture` 要求引用确切政策 ID、版本和内容哈希。
`RecipeReleaseStoreOptions.EvidenceCapturePolicies` 提供不可变的部署目录；发布、选择、
激活及每次 AcceptedTrigger 均检查确切引用，不回退到最新版本。已接受周期把
`EvidenceCapturePolicySnapshot` 冻结进 Admission。历史发布记录校验冻结引用、
已记录检查和签名绑定，不因部署移除旧目录项而失效。

All 保留所有有帧周期；FailOrUnknown 保留非成功执行或非 Pass 判定，包含
Success + Unknown 和执行超时后仍有输入帧；None 不创建图像义务。
任何政策下无输入帧均记录 NotAvailable 和实际采集失败原因。
NotRequired、NotAvailable 与带有 Manifest/工作项的 Pending 分别编码。

部署显式提供已有本地目录的 `ProductionImageStageOptions`、
`ProductionImageEvidenceStoreOptions` 和带暂存配置的 `ProductionInspectionOptions`。
暂存目录在构造和每次写入前检查本地固定 NTFS、非云同步、非 reparse 路径；
目录及大小、文件数上限参与配置哈希。政策目录与暂存配置参与生产配置指纹和武装检查。
不从旧 `ProductionEvidenceRequirement` 枚举猜测新留图政策。
旧构造器、旧无声明 Recipe 及未启用 ImageEvidence 的历史配置保留原行为和哈希分支。

## Canonical pixel content v1

文件内容为 32 字节固定信封与逐行有效像素；SHA-256 覆盖两者，输出大写十六进制。
协议名 `SharpInspect.CanonicalImagePixels`，协议版本 1。编码不包含行 padding、
显示转换、叠加层、PNG 编码参数、输入来源元数据或绝对路径。

| 字节偏移 | 定义 |
| --- | --- |
| 0–7 | ASCII `SIPIXEL1` |
| 8–11 | 大端 uint32 版本 1 |
| 12–15 / 16–19 | 大端 uint32 宽 / 高 |
| 20 | wire format：1 Mono8、2 Mono16、3 Bgr24 |
| 21 / 22 / 23 | ValidBits 是否存在 / 位数 / 保留零字节 |
| 24–31 | 大端 uint64 有效像素总字节数，不含信封 |

Mono16 采用小端、右对齐的 10/12/16 有效位，拒绝高位非零样本。
Bgr24 字节顺序为 B、G、R。尺寸、格式和 ValidBits 都影响规范哈希。
独立手工信封与冻结 SHA 向量位于 `CanonicalImagePixelContentTests`。

## 暂存、事务和发布

Coordinator 在把输入帧交给算法前取得独立 native read hold，不消费算法租约。
该引用保持同一预分配池中的实际规范输入，不重新采集或复制整幅图像。
算法关闭普通帧租约后，只要实际暂存 I/O 尚未结束，池槽位仍不可复用。

必须留图时，单操作暂存器依次创建唯一 `.partial`、写入信封及有效行、
`Flush(true)`、完整读回尺寸/像素/哈希，再在同目录原子重命名为 `.stage`。
暂存器随后通过提交期间持续持有的只读文件句柄再校验一次，以阻止文件被写入或删除。
只有暂存器内部签发的单次凭证可以进入 Core 提交；路径、哈希和调用者的布尔值
不能制造凭证。凭证绑定运行、Admission、留图政策、输入租约、暂存根及规范内容。

同一个 SQLite 写事务保存 Core、Pending Manifest、初始 `FinalizePng/Pending`
工作项和生产审计事件。提交前再次验证凭证保护与运行围栏；事务回滚不留下部分行。
Core 哈希绑定 Manifest 与工作项，冷读重建并逐字段比对两张侧表。
Manifest 还绑定采集元数据、来源、冻结追溯政策和权威图像保留规则。
Pending 未冒充已完成图像，也不启动尚未满足条件的最终图像保留计时。

EvidenceStageTimeout 使用单调时钟独立计时，之后才启动 TraceCommitTimeout。
阶段失败、校验失败、重命名失败、事务失败或到期都进入 Cycle Fault Termination，
不能发布普通结果。语义超时不提前释放仍在 I/O 中的帧引用；迟到完成只留下孤儿文件，
无提交回调，不能再补写 Core。实际 I/O 退出以前拒绝并发暂存，物理退役继续等待它。

积压额度同时约束项目数、规范字节数和最老年龄；数据库准入还预留在途周期预算。
额度内 Pending 增长不单独撤销 Arm；达到额度后阻止后续准入，已接受周期仍完成发布。
PNG 最终化不属于这条发布屏障，Pending 工作未编码 PNG 时也可发布已满足屏障的结果。
冷启动发现已有 Pending 或暂存目录非空会拒绝生产准入，等待后续正式对账能力。

## Schema 34 和迁移

ImageEvidence 显式启用 schema 34，要求生产检测、Recipe 草稿/发布/生命周期、
武装、身份及审计。新增配置、Pending Manifest、Pending 工作表和不可变触发器；
配置由恰好一次签名激活绑定。所有审计读路径传递并验证确切 ImageEvidence 配置。
schema 34 继续使用 schema 33 的身份/审计信封，不重写历史事实字节。

已有 33 库必须经 `SqliteStartupMaintenance` 的独占 33→34 计划迁移。
32→33 计划保持可用；其已完成日志作为新操作的哈希链接前缀保留，归档原永久标记。
切换标记采用同目录新文件、刷盘和原子替换，中断后永久名称保持完整旧标记或新标记。
新操作冻结图像配置哈希；不同暂存根或容量配置不能续跑同一迁移。
备份验证、源/目标指纹、提交意图、实际提交恢复及 Ready=false 继承 T49 的协议。
