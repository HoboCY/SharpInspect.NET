## 实现边界

本机 Graceful Stop 立即关闭生产准入并撤销 Ready。已耐久接受的周期继续采集、算法、
Core 提交和真实 PLC ACK 握手。Stop 的关联完成事实等待所属周期实际退休，并保持未武装。
重复 Stop 不替换正在等待的关联请求。未登录、锁屏或旧会话声明均不阻止物理本机 Stop，
但不获得 Arm 或其他管理权限；陈旧 WPF 展示仍可提交该受限命令。

Stop 在持久受理时保存所属周期的退休结果。即使 Fault Abort 及交付先于心跳收尾任务
完成，原 Stop 仍记录 Failed / ProductionStopInterrupted；后续空闲 Stop 不继承旧周期失败。
这避免把“采集已中止但消息交付成功”混同为正常完成检测后的停产。

Fault Abort 同步锁存当前执行关联的取消语义，并异步通知消费者。运行计算的取消信号
与耐久提交、健康 PLC 交付的有效期分离。尚未固定的执行产生 Cancelled + Unknown；
已经固定的 Success / Timeout、Core 和 payload 保持原值。采集取消及获取帧后算法尚未
进入的取消可生成对应的失败事实，不伪造算法结果或未发生的采集时间。

Core 事务不接收任意 UI/算法取消；仍使用原始提交期限、实际提交回执和最终有效性检查。
审计、存储、通信代次或控制器同步失效仍进入 Cycle Fault Termination，并保留原始
Inspection 与未决交付事实供 T44 恢复。报警的 ProductionImpact 决定是否取消当前工作，
Severity 不承担该决策。报警确认／复位不写 PLC 的 ResultAck、不武装，也不修复算法
超时导致的 Prepared 实例失效。

按 ADR-0088，已经固定的 Timeout / Cancelled 可以在物理算法尚未返回时完成健康交付。
相机预留、Prepared 实例和借用帧仍等待实际退休，新周期不能重入。T45 因此修正
V142_R12 原先“先等算法退休再交付”的实现及断言；不更改历史 T42 验证记录。
握手已经完成后发生资源退休失败，不再追加非法的 FaultTerminated 交付事件。

宿主受控关闭先撤销新工作，再请求当前计算取消。现有交付与 ACK 观察器在同一个
单调生产关闭期限内继续运行；期限耗尽后撤销交付权限，返回
ProductionInspectionShutdownIncomplete，保留未确认结果和实际资源所有权。
这属于未完成关闭，不能报告 Lifecycle.Stopped 或正常 Stop 完成，也不能据此重开工位。
挂起资源需要受控进程退出／重启及适用恢复流程。受控关闭成功后才完成通常的宿主清理。
不增加公开 API、协议编码、数据库 schema 或历史数据迁移。
