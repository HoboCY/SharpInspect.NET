# V1-28 显式算法配置迁移与新 Draft

关联工单：[Issue #29](https://github.com/HoboCY/SharpInspect.NET/issues/29)。

## 能力范围

`IAlgorithmConfigurationMigrationService` 接收显式迁移计划。计划冻结来源的
`DraftId / Revision / RevisionContentHash`、全新目标 DraftId、目标算法和 Schema、
迁移器 ID / 版本 / 内容哈希、OperationId 和变更原因。完整计划哈希作为 Step-Up
目标，授权操作类型为 `MigrateAlgorithmConfiguration`，权限沿用 `EditRecipeDraft`。
没有加载、打开历史或激活时自动运行的迁移钩子。

主机显式注册 `IAlgorithmConfigurationMigrator`。过程仅收到不可变来源配置、来源
绑定和目标算法描述，只能返回目标配置项和有界警告，不能返回整份配方、作者、会话、
批准或设备命令。旧算法 Factory 不必安装；来源使用持久化的原始 Schema 验证。
目标 Factory 必须按精确描述注册，其结构和语义验证复用普通 Draft 验证服务。
未知字段、错误类型或单位、缺失必需值、越界值及语义错误均拒绝；不填隐含默认值，
不钳位、不隐式转换单位。迁移输出的字段来源统一为 `Explicit`。

## 原子性、谱系与兼容

转换及目标验证全部成功后，既有 SQLite writer 在同一事务中重新验证完整历史、
精确来源、目标不存在、当前身份、权限和 Step-Up，然后追加新 Draft 的 revision 1
及身份审计。来源行、旧作者、旧内容和旧修订哈希保持不变。提交前失败或取消回滚，
提交完成后返回真实持久化结果。精确 OperationId 重放返回原结果，不再次运行迁移器。
新提交执行当前 Step-Up 检查；已提交请求的精确重放沿用 T15 的幂等契约，重新验证
当前会话、权限和授权修订，并匹配原签名授权及原 grant ID，不新增记录或再次消费 grant。
同一 OperationId 的相同计划并发到达时，后到者等待首次操作完成；不同计划立即拒绝。
等待者取得已提交结果后仍单独执行当前身份核验，不共享首个调用者的授权。

迁移谱系只保存一跳精确来源引用、完整计划、迁移器描述、输入配置哈希、最初输出
配置哈希和有界警告。整份内容经 payload hash、revision hash 和既有签名审计链绑定；
真实作者、会话、授权修订和 UTC 时间由持久化修订给出。后续普通修改必须保留同一
谱系，不能添加、删除、伪造或复制谱系到另一个新 Draft。再次迁移通过来源引用追溯
已有链，不复制无界的历史数组。

仅带谱系的内容使用严格 codec v4；该格式同时保留可空 provider extension 和可空
calibration requirement 数组。无谱系内容继续使用既有 v1–v3 字节和内容哈希。
原 `RecipeDraftContent` 和 WPF ViewModel 构造函数的二进制签名保留，通过新重载扩展。
没有新增数据库表、修改旧行、自动升级数据库或重新计算旧哈希。

迁移过程有注册数量、诊断数量和并发上限。不响应取消的过程在实际退出前持续占用
自身和全局执行槽；超时后的结果不会进入 writer。

## 界面与消费端

通用编辑器从选中的持久化历史修订发起迁移，单独选择目标算法 / Schema 和迁移器。
成功后精确重读新修订再打开；失败保留原编辑投影。界面展示来源与目标、迁移器身份、
输入 / 输出哈希、警告和谱系。普通修订继续保存不可变来源。

SampleHost 的 `--recipe-draft-check <目录> --configuration-migration` 使用真实 WPF、
身份服务、迁移服务和 SQLite，将开发示例的 `count` 显式改名为 `quantity`，再正常
修改新草稿。`--recipe-draft-query <目录> --configuration-migration` 在独立进程中
验证原来源及两个目标修订，不注册算法 Factory 或迁移器。示例合同与改名规则仅用于
开发消费端，不能视为项目迁移程序资格。
