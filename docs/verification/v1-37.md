## 行为与权威边界

资格会话由 Runtime 独占管理。Start 需要 `RunStationQualification` 权限、绑定当前命令和冻结计划的新鲜一次性 Step-Up、精确成功目标配置记录、生产禁用、无待交付和无冲突工作。已有 Station Acceptance 不是进入条件；缺失生产资格的原有 Recovery.Required 不会被清除。当前生产准入门仍按其自身证据判断。

目标按计划的精确 activation reference 读取。内部开发验证记录仍保留 `InternalContractFixture / DevelopmentOnly`，仅可用于明确声明为开发验证的设施；它不成为生产 Current，不改变 `CanBeActive`。这里冻结的是持久恢复目标及相机绑定代次，不声称它是进入前设备瞬态的实测值。隔离建立后通过实际 Apply/Effective 读回建立运行配置，退出时重新应用并核验同一持久目标。完整公共宿主从零创建成功 activation 的现有 `FrameworkQualificationAuthorityUnavailable` 边界仍保留。

宿主显式注册不可变计划与版本化受信设施。完整设施身份含版本、内容、覆盖路径及 DevelopmentOnly 声明；该声明不具有签发授权。计划分别冻结目标 Station Acceptance Fingerprint、候选、Profile、Qualification Context、目标控制器持久配置和瞬态控制器配置。普通命令调用者不能替换注册设施、指定运行 ID 或选择生产执行身份。

设施返回原始观察，Runtime 核验会话、租约 nonce、epoch、递增序列、新鲜 UTC、连接和安全停线、控制器读回以及五类目的地：生产 PLC 输出、普通 Outbox、MES、SPC、产量。隔离期间只有明确转向隔离测试目的地的 PLC 通道可以写测试结果；普通 Outbox、MES、SPC、产量输出必须禁用。释放隔离后验证目标生产路由且全部输出仍禁用。任何必需观察缺失均拒绝刺激。

每个资格刺激绑定冻结场景、上下文与控制器序列。Runtime 生成类型化 `QualificationRunId`，先持久化运行接纳再调用实际采集、算法和 PLC 结果编码核心。资格相机租约不允许 Commit、Preview 或 Manual 借用，并保留目标采集模式。输出是独立的资格 payload，不能作为生产 payload 或生产 Inspection 提交。

正常退出、取消、失联和重启统一撤销新刺激，等待真实物理工作退休，再在隔离状态恢复并读回目标相机和控制器，确认后释放临时隔离。调用超时不等于设备退休；恢复、读回或终态持久化失败保留阻塞。只有资源实际退休并有持久终态，停止等待才可完成。结束时保持 Disarmed，不签发性能、框架、Provider 或工位合格。

`RecoveryBlocked` 表示尚未完成的恢复责任，不是不可继续的会话终态；只有 `Closed + Restored` 完成会话。每次恢复保留原 Start Header，在事件中冻结当前 Runtime epoch 和新恢复 nonce，先持久化恢复身份，再等待旧租约实际退休并打开新的恢复设施。完整可信的失败记录可在冷启动时继续恢复；损坏或缺少绑定证据时不进行物理操作。恢复分支不能新增测试运行，仅允许取消旧的未完成运行。

WPF 工程页使用独立会话 ViewModel 和命名构造入口，保留既有 Shell ABI。打开页面仅查询；Start 重新认证，Exit/Abort 提交强类型命令。Accepted 仅显示已接纳，阶段与恢复来自 Runtime 查询。会话改变清空旧展示和敏感输入；界面取消等待不宣称 Runtime 已取消，迟到结果不能回填旧展示。
