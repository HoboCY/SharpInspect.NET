# V1-21 Hikrobot 受控单帧采集适配器

关联工单：[Issue #22](https://github.com/HoboCY/SharpInspect.NET/issues/22)。

## 交付与支持边界

独立 `SharpInspect.NET.Cameras.Hikrobot` 包依赖公共 Abstractions 与 Runtime 帧池；Runtime/WPF 不反向引用厂商适配器。
NuGet 的程序集负载仅包含该托管 DLL，并附安装说明；不包含或安装 MVS、驱动、原生 DLL、CTI、头文件或厂商 .NET wrapper。
生产兼容清单固定为空；公开构造器没有路径、SDK、模式、兼容清单或 override 参数。
公开 Provider 不加载 SDK、不枚举设备，Discover/Open 始终拒绝。依赖报告的本机路径保持 internal，普通 JSON 只含安全类别与数量。

设备集成方应从海康官方安装对应 Windows x64 MVS Runtime 与所用接口驱动/服务。常见 Runtime 位置为
`%CommonProgramFiles%\MVS\Runtime\Win64_x64`（也检查 x86 Common Files 下的相同 x64 目录）。
基础组件为 `MvCameraControl.dll`、`MVGigEVisionSDK.dll`、`MvUsb3vTL.dll`；诊断逐一检查同目录 native AMD64 文件，
不跨安装根拼凑组件。驱动/服务状态为 `NotVerified`，文件存在不被解释为驱动已经工作。
厂商 Runtime 自身的传递依赖与服务仍按厂商安装包提供，适配器不复制、不修复、不安装它们。

internal SDK 实现通过唯一、串行的实际所有者保持句柄。Open 后读回设备序列号；所有配置写完并完整读回后才产生 Effective。
任一校验、写入、读回、取消、配置失配使整机退出可用状态并退役；正在退役或清理失败时不会以 Closed/槽位空闲声称底层已释放。
受控采集先安装精确 pending，等待 Runtime Busy，再重检门并发出一次软件触发。
回调只校验、记录时间/计数并复制到一个预分配 raw slot；规范化、帧池复制和消费者 continuation 在栈外执行。
早、多、晚帧丢弃并记录到容量 64 的协议环，不跨请求缓存。SDK 内部缓存固定为两个节点，适配器像素池无堆分配兜底。
已安装采集请求发生取消或超时时，设备进入整机退役；软件触发命令返回不能被解释为曝光与回调已经结束。
采集任务保持物理清理占用，直到 Stop、注销回调、栈外工作及设备句柄释放得到确认，迟到帧不能转归新请求。
Runtime 关闭控制门与异步取消通知之间的间隙同样触发退役；主动 Stop 不能提前完成采集并释放物理占用。
硬触发帧的 Busy 里程碑直接取自对应控制对象已经发布的不可变 Start，不依赖适配器等待续体的调度顺序。

工程候选每个物理句柄最多注册一次回调并安装一次 pending。任一采集终态后该会话永久消费，健康为
Disconnected/Unknown/Stopped，Start/Acquire 以 `HikrobotSingleFrameSessionConsumed` 拒绝再次使用。
单帧成功按规范化就绪交付 lease；旧句柄仍由 Provider 保有，只有实际 Dispose/Close/Destroy 完成后才可重新 Open。
注册回调后的 idle Stop 同样退役整个设备，不能 Stop/Start 重用旧 delegate。旧帧只能成为旧相关 ID 的 Late/Unmatched 事实。
当前不支持同一句柄重复采集；SDK 停止/注销对内部排队回调的实际后置条件仍为 NotRun，不能用 shim、时间窗或帧计数推定。
native 能力仅含 SoftwareTrigger；Native Apply 在 SDK 调用前、工程探针在 SDK 加载前，以
`HikrobotHardwareTriggerNotQualified` 拒绝 HardwareTrigger。仅存在 Line0 节点不能证明 Busy 前的物理脉冲没有被 SDK 缓冲。
托管 seam 的硬触发测试验证已送达回调与控制门的时序、取消及占用，不代表 native 硬触发能力或其物理资格化。

首个 native 候选限定文件版本 `4.8.1.2`，加载前校验 native AMD64，加载范围仅为该 DLL 目录与 System32。
SDK 版本查询必须与文件版本一致。生产兼容清单仍为空，SDK 加载成功也不改变它。
native 能力仅公开实际枚举到的 Mono8 / unpacked Mono10/12/16，ROI 范围保留设备当前返回的子集；
RGB/BGR 规范化已有托管实现及夹具，真实彩色机型的白平衡单位/完整配置仍待匹配型号验证，因此不宣称 native 彩色支持。
详细头文件/Runtime 版本差异与哈希见 [SDK 来源证据](hikrobot-sdk-sources.md)。

## 另行授权后的设备探针

以下只是一份交付的测试入口，本次没有执行。先在隔离测试工位安装 Runtime/驱动，确认独占设备与完整软件触发配置。
准备 JSON 文件，九个顶层字段必须全部显式存在，例如：

```json
{
  "productionAcquisitionMode": "SoftwareTrigger",
  "exposureTimeUs": 1000,
  "gainDb": 0,
  "regionOfInterest": { "offsetX": 0, "offsetY": 0, "width": 640, "height": 480 },
  "pixelFormat": "Mono8",
  "validBits": null,
  "acquisitionTimeoutMs": 1000,
  "triggerDelayUs": 0,
  "whiteBalanceRgb": null
}
```

像素格式、ROI 和数值应改为该设备实际声明的能力；不能用示例证明型号支持。
SDK DLL 哈希、设备身份、型号与输出目录均需显式提供。型号缺失时绑定文字 `Unavailable`。
Runtime 上限 64 MiB，配置上限 8 KiB；流式哈希与有界读取期间保持同一文件禁止写入/替换，
该文件所有权持续至探针退出，防止校验的字节与执行、记录的输入发生替换。

```powershell
dotnet build samples/SharpInspect.Hikrobot.DeviceProbe -c Release
./tools/Invoke-HikrobotDeviceProbe.ps1 -AllowDeviceAccess `
  -RuntimeLibrary $absoluteInstalledSdkDll -RuntimeSha256 $expectedSdkSha256 `
  -StableDeviceIdentity 'GigE:EXPECTED-SERIAL' -ExpectedModel $expectedModel `
  -Configuration $absoluteConfigurationJson -OutputRoot $newAbsoluteEvidenceDirectory
```

脚本创建隐藏子进程，默认 60 秒上限；超时终止该探针进程并保留 stdout/stderr/进程证据。
完整配置采集时限最多 10 秒。成功时记录设备、Effective、FrameMetadata、FrameProvenance 和有效像素 SHA-256，
返回 lease 后完成退役。该结果始终是 `developmentDeviceObservation`，`hardwareQualification=NotRun`、`productionReady=false`；
不会创建生产兼容记录或授予生产权限。
