## 冻结合同与身份

`PerformanceContract` 必须显式提供六类场景（ColdStart、SteadyState、Burst、Stress、Recovery、Soak）、
数据集与刺激身份、逐周期有效像素哈希及清单哈希、预热与测量周期数、最短／最长时长、触发间隔与突发结构、
绝对节拍偏差上限、停止／恢复次数、预期失败序号及原因、全部分段和资源的适用性与预算。
合同还绑定统计规则、采集器描述哈希、构建配置、进程架构、电源配置、调试器／Profiler 与诊断配置。
所有集合防御复制；具名预算和场景按固定键规范化，逐周期帧清单保持序号顺序。
修改任一已绑定字段会改变合同哈希。没有隐含通用生产阈值。
未指定节拍容差的场景为 Unproven，不能通过；缺少场景或同一场景重复提交均不能汇总通过。

`ProductionStoreOptions.PerformanceMonitoring` 绑定合同、部署声明和健康清除周期数。
实际监测绑定进入 `ProductionConfigurationBuilder` 的 Performance 指纹；未配置或部署声明不匹配时，
生产部署检查不通过。有限基线开关也进入指纹，选择的场景及 RunId 单独记录。
每次耐久接受还记录实际准入 Performance 指纹；同一基线内变更目标会失败。
运行头记录实际程序集哈希、QPC 频率及环境观察；未知观察不会用声明值顶替。
DebuggerPresent 取 `Debugger.IsAttached`；ProfilerPresent 按当前进程的
`CORECLR_ENABLE_PROFILING`／`COR_ENABLE_PROFILING` 开关是否为 1 采样。
动态附加及其他诊断工具的现场环境证明属于后续正式 Profile 的未执行项。

持续健康监测和有限证据捕获分开：仅配置 BaselineScenarioId 才保留该次固定场景的原始记录。
捕获在 Runtime 构造时开始，在显式最长时限或 Runtime 关闭时封存。计时包含初始化及关闭前等待，
不会事后截短为有利窗口。过期时实际封存时间超过冻结上限也会失败。
读取接口 `IPerformanceMonitoringQuery` 只读；捕获尚未封存时返回 null。

## 单调时间与失败分母

固定 Runtime／适配器在实际事件边界记录 `Stopwatch` 时间戳：

| 分段 | 起止边界 |
|---|---|
| TriggerToBusy | 控制器触发采样完成 → Busy 物理写入完成 |
| Acquisition | Busy 写入完成 → 规范化帧可用 |
| AlgorithmQueue | 提交算法任务 → 实际调用算法 |
| AlgorithmExecution | 实际调用 → 实际返回／抛出 |
| ResultValidation / PlcEncoding | 对应校验／编码开始 → 完成 |
| DurableImageStage | 必需留图暂存开始 → 完成；冻结 None 为 N/A |
| CoreTraceCommit | Core 构造／批次准备开始 → 耐久事务回执 |
| RuntimeResultLatency | Busy 写入完成 → ResultValid 写入完成 |
| ResultAcknowledgement | ResultValid 写入完成 → 实际 Ack 高采样 |
| AcknowledgementResetToReady | Ack 低采样 → 下一次 Ready 写入完成 |
| ReadyToReady | 本次触发前 Ready → 周期退休后的下一次 Ready |

UTC 只用于展示／关联，不参与耗时相减。事件发射顺序可以晚于实际观测时间，计算按所记录单调边界。
算法超时不会伪造物理返回；缺失阶段与失败保持可见。预热按耐久接受序号排除统计，原始数据保留，
失败不会重新编号或替换。已完成且成功的耗时采用 nearest-rank：`ceil(p*n)-1`，
Observed Max 为样本最大值，jitter 为样本最大值减最小值；空集合全部为 null。
每个分段另列成功样本、失败、Unknown、N/A 和证据缺陷数。适用阶段不能自行用 N/A 规避预算。
冻结预期失败仍计入失败数及 MaximumFailures；未出现或原因不符时失败。

原始接受、Core、AckReset 和 FaultTerminated 与已验证耐久账本逐项核对，区分业务丢失／重复与观测缺失／重复。
Correlation、InspectionId、控制器周期分别检查唯一性；后续事实身份必须继承所属接受。
持久 Core 的 ExecutionStatus 参与失败分类，成功执行的产品 NG（Decision.Fail）仍是正常业务结果。
实际输入仅在有限基线中计算有效行像素哈希；包含尺寸、像素格式、有效位数，不包含行 padding。
哈希工作有显式字节上限，其成本包含在端到端耗时中。日常持续监测不执行该逐帧哈希。

## 资源与预算隔离

固定采样器输出 42 项具名资源：进程 CPU、WorkingSet／Private、GC 堆／提交量、分配／GC 次数及暂停、
线程／句柄、固定帧池容量与 Lease、SQLite／WAL／写队列／checkpoint、图片／Outbox／诊断队列，
以及 WPF 快照、复制、绘制的成功数、累计耗时与独立失败数。
CPU 是进程 CPU 时间增量除以单调时间和逻辑处理器数。每周期分配是进程区间增量，不声称算法独占分配。
GC 堆数据来自最近一次完成的 GC，不强制 GC；漏过 GC 索引后暂停覆盖为 Unknown。
精确 NativeMemoryBytes 在当前平台采集器中为 Unknown；NonGcPrivateBytesEstimate 只是独立估算值，不能替代原生指标过关。
没有注册 WPF 查询、无法读取文件／计数器等均保持 Unknown／null。只有确证不存在的 WAL 才记为零。

有限数组和共享字节预留控制原始观测量；容量不足／争用丢失不会覆盖旧样本，封存为 Incomplete。
导出另按冻结 MaximumBytes 检查完整 UTF-8 文档，超限拒绝导出，不截断证据。
持续监测仅保留当前周期固定时间槽及健康计数。资源采样同时最多一个实际调用；
超时后保留物理槽直至实际返回，不创建替代调用。关闭超时先原子占有失败终态，迟到成功不能替换。
封存切换时若仍有进入捕获的生产者未退休，立即保留不可清除的完整性不确定标志，报告为 Incomplete；
不会等待这些生产者，也不会把尚未确认的完整性当作无丢失。
资源报告输出峰值、首／末值、增长、样本和 Unknown 数；仅累计计数器下降判重置，普通内存／队列下降正常。

预算超限独立于硬超时，不重写 ExecutionStatus、Decision、Core 或报文。
性能告警只能映射 None 或 BlockNewTriggers；FaultAbort 配置拒绝。
None 保留完整告警账本，但不改变生产许可所依赖的准入材料；BlockNewTriggers 阻止后续接受，
已经接受的周期仍执行提交、发布、Ack 和退休。正常硬超时与其他故障政策仍生效。
None 下只有达到冻结的连续健康周期数才清除超限标志；BlockNewTriggers 不自行放行一个试探周期，
需按现有停机／重新启动和准入流程处理，不能用观测接口复位生产权限。

WPF 计数只累加标量，读取不调用 Dispatcher。成功次数／完整复制字节保持成功语义，
失败操作已经消耗的时间在 finally 累加，并单列失败数。Dispatcher 尚未执行 action 就失败时没有 apply 时间。
原生 Channel DropOldest 回调只统计被淘汰快照，断连标记不计；不使用 received−applied 推算精确队列数。
各计数分别原子读取，不声称跨字段事务快照。

## 导出与复算

`PerformanceEvidenceDocuments.Encode/Decode/WriteNewAsync/ReadAsync` 提供版本化 UTF-8 文档，
包含合同、实际头、原始事件／资源／帧哈希／周期绑定／账本引用、计算规则及报告，分别记录 raw/report SHA-256。
离线读取只重建封闭类型及其验证构造器，然后重新计算所有合同哈希和完整报告，与规范字节逐字比较。
对象字段按 Ordinal 名称排序，数组维持原始顺序；不依赖不同 JSON 运行时的反射／构造参数属性排序。
未知／重复字段、篡改报告、过期计算规则、非规范表示或超大输入被拒绝。
文件写入先创建唯一 pending 文件，flush 后移动到新目标；绝不覆盖旧文档，失败 pending 留作证据。
这些本地哈希不认证外部输入来源，也不是资格签名。

独立消费程序支持 `--inspect <文档>` 查看统计、失败和 Unknown。
默认 smoke 验证公开 API、不可变合同、缺失证据的失败及 NotRun 语义；不把合成输入声称为实际周期。
T57 整仓脚本另将实际虚拟周期文档交给仅引用 NuGet 的消费者，在核对捕获时的 Runtime／Abstractions
程序集与所用包相同后要求独立复算通过；该要求不是以同进程 encode/decode 代替。
