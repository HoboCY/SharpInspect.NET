## 像素与所有权

Frame Metadata 验证尺寸、正 Stride、像素格式、Valid Bits、Host UTC 和公共 Effective Camera Configuration。
最小覆盖为 `StrideBytes * (Height - 1) + ValidRowBytes`，按 checked long 计算。
源可不含末行 padding，但池自身和 native read hold 必须覆盖 `FullBufferLayoutLength = StrideBytes * Height`，
因为 OpenCV 的 `datalimit` 指向完整物理行布局的末尾。例：3×2、Stride=5 时，source=8 可接受，pool 必须至少 10 字节。
该 native 边界依据 [OpenCV 4.11 matrix.cpp](https://github.com/opencv/opencv/blob/4.11.0/modules/core/src/matrix.cpp)。
Mono16 只允许右对齐小端 10/12/16 位，拒绝非零未用高位；Bgr24 使用交错 B/G/R。
复制按源 Stride 读取有效行，并清零输出全部 padding，包括末行 padding。
OpenCV 要求 row step 是标量元素大小的倍数：Mono16 的奇数源 Stride 在池内归一为下一偶数，
输出 Frame Metadata 显式报告新步长；Mono8/Bgr24 保持原步长，所有路径都不压缩已有 padding。
例如 2×2、Mono16 Stride=5 的 9 字节源，复制为 Stride=6 的 12 字节 backing，Mat 使用真实 Step=6。
归一化使用预分配像素槽；桥不会暗中分配替代缓冲，未经归一化的 Mono16 奇数步长在调用 native 前稳定拒绝。
输入超出已配置槽大小、源覆盖不足、取消和预算超限都不交付 frame。
预期生产帧超过槽容量也按 `FrameBufferExhausted` 返回 Error/Unknown 并原子锁存故障；空槽不能掩盖容量不足。

Pool 在构造时一次分配全部 pinned 像素内存。最多 64 槽、单槽最多 64 MiB、总量最多 512 MiB，
启动使用 checked 计算；调用方必须显式指定容量、最大帧字节和回调工作预算，后者上限 1 秒。
这是开发资源边界，不是产线合格参数。生产热路径无像素数组或 native pixel buffer 的耗尽兜底，
但成功租用仍创建小型 owner、frame 和令牌对象，不声称整个流程零托管分配。
预算在复制前、逐行及结束时检查；操作系统调度和单个有界内存操作无法被强行抢占，超预算返回稳定错误并归还槽。

每次租用有独立 owner 和 LeaseId。归还与获取 native read hold 在同一锁内竞争；
只有 owner 已关闭且全部 native read 都退出后才能回池。旧 frame 对象不会因槽被下一帧复用而重新激活。
FrameBufferLease 的幂等释放只关闭自身 owner；原生 view 不持有释放像素所有权。
池关闭拒绝新租用，并保留已有 owner/read 所需 pinned 内存；最终归还才移除其根引用。
复制到交付的切换使用 copying→owned CAS；关闭先赢时只标记 copying 槽失效，不提前清掉仍在复制的缓冲。
发布先赢的 owner 继续按已有租用规则保留。受控测试在发布前设置内部 barrier；公共构造与 DI 不能安装此探针。
已经返回的 ReadOnlySpan 无法撤销，未来执行器必须持有 owner 到实际 ExecuteAsync 退出，
不能在逻辑超时发生时就复用缓冲。本票不声称已交付 T13 的执行期隔离。

FrameCallbackHandoff 使用 `FullMode=Wait` 加 `TryWrite`，无静默 Drop 模式，
`AllowSynchronousContinuations=false`。发布在所有结果下消费原令牌：成功转移给队列，失败负责释放。
原令牌不能再访问/释放新所有者；领取后获得新令牌并保留同一 LeaseId。
仅允许一个待完成读操作，取消等待不会丢弃别人排队的帧，关闭会 drain 并释放未领取 owner。
池与队列不在 SDK callback 栈执行算法、Runtime、UI、日志或数据库工作。

## 元数据与来源

算法侧只有类型化相关 ID、Logical Camera Role、规范布局、UTC 和公共有效相机设置。
公共设置明确包括 ProductionAcquisitionMode、ExposureTimeUs、GainDb、ROI、PixelFormat、ValidBits、
AcquisitionTimeoutMs、TriggerDelayUs 和固定 WhiteBalanceRgb，所有生产值显式提供。
白平衡是有限正数通道比率，不能用 8 位显示色替代；实际相机能力范围和增量还需 Provider 验证。

独立 Provenance 保留同一相关身份、Provider/adapter/SDK 版本、物理设备、可缺 model/firmware/native runtime、
原生格式、规范化分配/变换标记、可缺 Device Timestamp/frame counter、UTC/单调里程碑。
缺字段保持缺省。单调点按所有存在项顺序核对，UTC 可以因调时而倒退；设备时间不被推断为 UTC 或权威关联键。
本票提供证据 DTO 与相关绑定，实际生产追溯持久化和 Provider 读取由后续工单交付。
输出 Provenance 的不可变 `PoolCopyEvidence` 记录源/目标 Stride、像素恒等复制、padding 清零和预分配槽使用。
源 Provenance 不修改，自由文本和分配标记保留；顶层变换标记累计池对齐，证据另保留输入变换标记，
使 Provider 与池变换仍可区分。结构化记录不拼接受长度限制的原详情。

## OpenCvSharp 消费边界

独立 `SharpInspect.NET.OpenCvSharp` 包仅引用 Abstractions 与 OpenCvSharp4 托管包。
`WithMat` 在真实指针与 row step 上构造 header；同步回调的 finally 先释放 Mat，后释放 native read hold。
显式 Clone 的分配与释放归调用方。Mono16 显示副本以完整 Valid Bits 量程进行整数四舍五入缩放，
不改变算法输入或用 8 位副本替代权威图像。
原始 Mat 可写，也能被不合规代码另建 header；本票只保证框架创建的 header 和 loan 生命周期，
不将进程内契约描述成 sandbox。算法须通过后续消费代码审查和真实资格验证。

固定依赖为 [OpenCvSharp4 4.11.0.20250506](https://www.nuget.org/packages/OpenCvSharp4/4.11.0.20250506)
及样例显式引用的 [Windows runtime 同版本](https://www.nuget.org/packages/OpenCvSharp4.runtime.win/4.11.0.20250506)。
外部像素 header 的所有权和 step 依据 [官方 Mat 实现](https://github.com/shimat/opencvsharp/blob/main/src/OpenCvSharp/Modules/core/Mat/Mat.cs)。
最初评估 4.13.0.20260627 时，实际样例构建报 CS9057：包分析器依赖 Roslyn 4.14，当前 SDK 8.0.319 为 4.10。
最终选择兼容版本；未升级冻结 SDK，也未关闭 .NET/xUnit 分析器或扩大 warning 抑制。
