## 状态与来源边界

Alarm Policy 显式绑定 Code、Source、版本、内容哈希、Severity、ProductionImpact、锁存、通知、PLC 映射及观测有效期。
严重度只表达关注程度，生产影响独立使用 None、BlockNewTriggers、FaultAbort。
同一次连续发生保持同一 InstanceId；清除后复发建立新实例。PLC 只显示有界摘要，完整未清除实例仍保留在 Snapshot 与历史中。

只有 Runtime 内部受信来源可以提出观测；公开 WPF 和宿主命令不接受 sourceHealthy 或 prerequisitesPassed。
当前真实来源为 StartupRecoveryRequired，直接从 Runtime 的 Recovery 状态读取；设备健康正向场景使用内部开发夹具。
观测的接收年龄由 Runtime 单调时钟计算。旧 Runtime Epoch、倒序或过期的健康证据不能授权复位。
Runtime 只接受精确下一序号，拒绝跳号与 long.MaxValue，不让来源污染后续序号。
观测有独立的 16 槽入口；排队观测让本机 Stop 的受理和终态事务优先，已开始的原子写入仍受提交期限约束。
后续 Provider 适配器还必须在提交 Runtime 观测前拒绝自身过期的 provider revision。

ACK 是个人看见该实例的审计事实，不清源、不解锁存、不处理 ResultAck、不完成 Manual Recovery、不 Arm。
Reset 重新检查当前实例、同代次新鲜健康源和该实例绑定政策的专属前置；只解除对应锁存。
默认 Operator 可 ACK，Technician/Administrator 可 Reset；Reset 默认要求 Step-Up，绑定本次命令与精确实例 ID。
授权政策额外要求 ACK Step-Up 时，样例页面按实际政策取得绑定 ACK 的 Grant；密码框在提交或页面清理时清空。

## 持久与查询边界

本票扩展身份存储为 schema 7，旧 schema 6 要求受治理迁移，不能自动升级或重写已有证据。
报警策略和事件与现有签名审计链绑定；个人命令的身份检查、Step-Up、报警转换和命令事实在同一事务提交。
政策表的 ID、版本、hash、内容及激活时间须匹配签名中的 PolicyActivated 原始载荷。
事件签名包含 Runtime Epoch 和 System Principal，查询核对全部索引列，不能用可重算的普通 hash 代替签名权威。
PLC 摘要由完整未清除实例重算，并校验其与最后持久投影一致；未知 Code/Source 边界故障保持阻断，不隐式配置默认政策。
历史查询使用有界 keyset 分页和固定 ThroughPosition；投影与 UI 均不能修改历史。
当前开发实现对配置了报警的存储从 genesis 到本次 tail 完整核验，再按索引与 SQL LIMIT 读取页面。
核验受时间和 `MaximumVerificationEntries` 双重约束，默认上限为共同审计链的 10000 条；不能覆盖全部依赖时返回不可用，
不把最新检查点后的局部核验当作旧报警可信证明。长期保留、分段证明和容量资格留待后续工单。
无 AlarmPolicy 的已有身份存储保留原核验语义；旧 schema 的 64 KiB SQLite 值上限不因本票放宽。
