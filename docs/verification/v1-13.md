## 时限与不可变结果

`AlgorithmExecutionPolicy` 显式指定部署策略 ID/version、最小/最大执行时限和取消宽限期，
使用规范化的身份与 ticks 计算 SHA-256。所有时长必须正、整毫秒且不超过 int.MaxValue 毫秒，最小值不得超过最大值。
该上限是 .NET 定时器的结构边界，不是工业现场推荐值。框架不提供隐式生产时限或 grace 默认值。
`AlgorithmExecutionRequest` 提供 Recipe ID/version/content hash 和请求期限；无效数据在接管 frame owner 后拒绝，
不会泄漏本次帧令牌或进入算法。Recipe release/activation 权威流程由后续工单实现，此 DTO 不宣称 Recipe 已发布。

引擎在接纳请求时绑定不可变 `AlgorithmExecutionTimingSnapshot`，Outcome 保留相同的策略/Recipe 身份、
hash、有效时限、grace、单调起点和频率。新配置不能改写已接纳请求；UI 和算法都不能改变已绑定数值。
从 attempt 建立起，调度、实际 Execute 和完整结果校验均计入执行期限。
截止先固定 Timeout + Unknown，Runtime abort 在未到截止时固定 Cancelled + Unknown。
只读 Outcome 不保留迟到结果、measurement、Overlay 或异常；迟到数据不能重新解释终态。

取消信号在独立任务中执行消费方 callback，不阻塞发出 Runtime abort 的调用方。
固定终态时同步向进程 guard 登记不可变 grace 记录并启动有界监视；实际 Execute、结果校验及取消 callback 全部退出前保留帧和实例借用。
健康读取、最终准入与物理退出都在 guard 同一锁内检查单调 grace 边界，避免调度延迟导致监视任务漏判或开放新调用。
进入用户 Execute 前还会复核执行期限；即使工作任务调度迟到，也不能在期限已过后启动用户算法。
实际调用在 grace 内退出可安全归还帧并退休该实例；再次准备仍须通过 Factory、配置验证、WarmUp 和普通准入。
实例物理 Dispose 仅在上述调用全部退出后发生；退休失败保留引擎阻断，不能把失败对象重新使用。
安全退出会取消监视器自己的 Delay，避免长 grace 单独保持已退休的 attempt；该私有 token 不向算法暴露。

## Hung 与宿主恢复

`AlgorithmExecutionGuard.CurrentProcess` 是构造器封闭的进程级永久锁存，保存首次 Hung 的关联 ID、
prepared instance、frame lease、固定状态、绑定时限、单调观察值和 UTC 观察时间。没有 Reset API。
超过 grace 后仍未退出即锁存；执行服务和准备服务都检查它，准备交付与 Hung 锁存在同一锁内互斥。
重建引擎、准备服务或 DI 容器不能创建健康的替代锁存。已经进行中的准备也不能在 Hung 后交付新实例。
迟到退出允许真实清理资源，锁存本身仍永久保留。

Runtime 同步投影 Hung 为 Ready=false、Disarmed 和 AlgorithmHung 准入阻断，独立于异步 SQLite 报警写入。
启用执行服务的 Runtime 要求受信任 Runtime.AlgorithmExecution 来源的 latched 阻断报警映射；
映射缺失或不适用则报警权威不可用并拒绝生产。报警正常时经既有签名链写入，ACK/Reset 不会清除进程锁存。
Hung 后不发送健康观察。库不调用 Thread.Abort、不强制 Dispose 借用、不卸载程序集、不终止当前宿主进程。
恢复依赖外部受控宿主重启，然后再次经过启动协调和生产武装门禁。
