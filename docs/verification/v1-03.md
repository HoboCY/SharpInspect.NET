## 政策与信任边界

部署输入钉住 Station、Policy 内容及密钥目录/名称；数据库不能选择信任根。
全新空库和显式开发 bootstrap 才能创建新机器保护密钥和 SystemPrincipal genesis。
已有密钥配空库、现有 schema2 缺失密钥或 genesis、政策或签名失配都失败，不自动覆盖或重建。
密钥创建与数据库事务之间无法原子提交；失败后的孤立密钥保留，下一次初始化拒绝复用。
schema1 启用政策在只读 preflight 拒绝，正式治理迁移属于后续工单。

查询先验签可信 checkpoint，再连续验证所请求段，包含回溯前缀并受政策总预算限制。
政策总预算至少为检查点间隔加上默认 200 项或后台页长的较大值；公共页长上限预留完整检查点间隔。
schema2 当前只有 genesis 和 CommandFact，按索引极值及段内逐项序号验证覆盖关系；增加新事实类型时必须版本化扩展该约束。
锚定使用已持久回执的唯一 Sequence 索引推进水位；历史分段同时核对其检查点回执，后台历史核验按政策间隔节流。
每次追加在写事务内重新核验当前可信检查点至尾部，保留原始结构故障并回滚；事务内不调用外部服务。
所有政策开启的提交都立即转为待核验并唤醒尾段复核，后台旧观察不能覆盖已锁存故障。
报告区分启动尾段、历史局部段、整个当前保留范围，不从 UI 上界或游标建立信任。
已认证人员、权限/Step-Up 和生产初始化均未交付；输入中的管理员名称不能获得更正、删除或密钥管理权。

首次 CNG MachineKey 候选在本机实际返回拒绝访问，测试失败，未算作最终机制通过。
最终选择的 DPAPI LocalMachine 机制已在新候选实际验证；不提升进程权限，不改变系统 CNG 目录权限。
DPAPI 加密私钥只在内存中解保护供签名，文件访问由受限 ACL 保护，不能称为硬件不可导出。
所有 SQLite 入口在读取 schema/事实/JSON 前限制单值为 64KiB。公开核验最多 2 个执行、32 个在途或等待；
政策单次含可信前缀最多 10000 项。外部适配器即使不遵守取消，也最多保留一个调用。

第一份完整运行 `20260907-194318-723` 的 87 项测试及 smoke 曾通过，但截图发现面板重叠，
审查还发现损坏 JSON 分类不足；它不作为最终候选验收。修复后增加实际布局断言及损坏/超大证据回归，
