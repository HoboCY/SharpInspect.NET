# V1-30 版本化政策下的不可变配方发布

工单：[Issue #31](https://github.com/HoboCY/SharpInspect.NET/issues/31)。依据父规格 D16、
ADR-0093 / ADR-0095、US-43 / US-53 / US-55 与验收族 T17。
起点为已发布的 T29：`581afe132b8dcefc8fb9eef61baca8bcd34497f3`。

## 实现边界

部署显式配置不可变 `RecipeGovernancePolicy` 的 ID、版本和模式；其内容哈希绑定完整政策。
`SingleApproverRelease` 允许作者审批自身草稿，`MakerCheckerRelease` 要求审批人不是
当前内容的任何贡献作者。未配置发布能力的旧草稿部署继续使用原模式，不能隐式获得发布能力。
新存储通过 `ProductionStoreOptions.RecipeReleases` 明确选择 schema 16；既有数据库不自动升级。

`ReleaseRecipeCommand` 绑定草稿 ID、准确修订及修订哈希、完整治理政策引用和发布原因。
批准与发布是一次原子操作，不存在可复用的批准对象。Runtime 在审批前验证准确保存内容的
结构、完整配置、注册算法描述和算法语义，在写事务内重新核对草稿头、真实人员权限、
新鲜 Step-Up、所有声明依赖与贡献作者。审阅期间即使只新增内容相同的修订，也必须重新审批。

贡献投影 `sharpinspect-recipe-contributions-v1` 按语义字段记录当前贡献：配方和算法身份、
配置与来源、相机字段、政策与资产引用、标定要求、扩展与迁移谱系。无变化保存不增加作者，
实际覆盖由新作者承担，删除贡献以墓碑保留。迁移递归读取准确源修订，相同复制字段继续保留
原作者，改变字段和迁移谱系属于迁移执行人。账号重新登录不改变人员身份。

依赖验证使用本地权威记录。算法执行政策必须精确匹配；声明的治理政策必须与部署一致。
标定要求解析准确发布的验收政策及其用途、类型、系数契约，不在配方发布阶段要求当前相机、
物理核验、工位绑定或投产资格。历史回读也不能用发布之后才出现的政策补证。
尚无权威解析能力的模型资产、其他政策或相机扩展依赖明确拒绝，声明哈希本身不构成可用证明。

成功事务同时写入命令结果、身份授权与不可变发布记录，并受中央审计链及外部锚点保护。
配方引用的内容哈希为准确源内容哈希，审核记录另有绑定审核门、变化、作者、审批人、授权
政策、Step-Up 和时间的记录哈希。版本按配方键递增，旧版本不变；结果只形成 Available，
不选择 Active Recipe、不武装、不创建或执行算法。只读查询在独立快照中验证历史，不启动
writer、算法 Factory 或设备。

WPF 只允许发布当前准确保存且有效的内容。输入或会话变化会撤销界面中的可发布投影。
提交成功后才到达的取消信号不改写实际提交结果；已切换的界面也不会被旧操作结果覆盖。
