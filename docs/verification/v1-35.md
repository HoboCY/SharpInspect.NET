## 行为范围

- 当前用户须有 `RunManualInspection` 权限；Runtime 分配 Manual session/run ID，保持 `Ready=false`、Disarmed，并保持独占约束。
- 来源必须是精确的、未放弃的 Draft，或精确可用的 Released Recipe。Draft 可以在没有 Release 或当前 Active 的情况下临时 Prepare；Retired 只能复制为新 Draft 后再评估。
- 复用现有受控 Camera、Frame Pool、Algorithm Prepare/Execute、Schema、Lease 与超时治理，使用同一已准备实例产生 Pass、Fail、Unknown。
- 手工结果只进入独立 Manual ledger 和证据；手工身份只表示操作者或适用的 Part Identity 来源，不产生 Inspection ID、生产 PLC 输出、产量、MES/SPC、普通 Outbox 或资格证据。
- Graceful Exit 和本机停止排空已受理 Run；Abort、登出、权限失效和关闭由 Runtime 取消。调用方等待 token 的取消不会取消已受理工作。
- 退出后恢复持久的 Active Camera 基线并读回；没有 Active 时安全关闭。准备、执行和相机工作实际退役前不释放资源；恢复失败保持禁用和 RecoveryBlocked。
- 冷启动读取已验证的未完成责任，完成安全退出或恢复；不会制造成功的检测结果。

## 已知范围限制

- 实际 PLC trigger ingress 尚未实现；手动命令边界不能替代真实 PLC 触发入口。
- 没有真实硬件或生产 qualification。Virtual Camera、开发夹具和局部集成测试不等于工位验收。
- Draft abandonment 与 Released retirement API 尚未实现。选择以当前精确 query 的身份和可用性为准，不能用测试伪造缺失的生命周期 mutation。
- immutable baseline hash 绑定的是历史观察到的 exact baseline；恢复后的 readback 具有新的时间和 reason，不能把新的时间/reason 当作历史值。
- public host 同时验证 Active 与 temporary/manual prepared instance 时，需要足够数量的 algorithm owned instances；单一实例不足以证明两者可并存。
- 只读 query 的文件快照允许 SQLite 维护 `-shm` 共享内存元数据，并允许新出现且长度为零的 `-wal`；已有 WAL、非空 WAL、数据库内容、签名 key 或其他文件发生变更仍会失败。元数据例外不表示数据库或 key 被写入。
- 诊断只呈现实际 safe reason code 和 dropped diagnostic counts；不编造已接收的诊断流或成功事件。
- 未解析的资产、标定或设备要求保持拒绝，不会转化为手动检测的生产资格；生产 PLC payload、MES/SPC、yield、Outbox 和 qualification authority 仍必须由实际 query/count 证实为零。
