## 实现边界

生产入口使用 T40/T41 的同一个周期协调器、Modbus 传输、观察器、输出锁和双向通信健康判断。
`ModbusProductionProfile` 区分生产 Ready 位与资格 Ready 位；完整端点、寄存器、时间政策进入不可变哈希。
Trigger 必须通过当前来源身份、代次、序号去重以及 Runtime 的实际准入和 Arm 检查。
Runtime 在采图前分配 Inspection ID，冻结控制器周期、激活快照、通信许可与 Trace Storage Policy，
并将 Admission 先写入耐久账本。Inspection ID 与控制器代次/序号独立，保留两者关联。

本阶段显式支持 Evidence=None、零路由、Part Identity=None。
Required/Optional 部件身份、图像留存和外部路由不降级为 None；未实现的必需政策拒绝激活或准入。
生产目标从实际加载的框架/算法/工厂/provider 二进制、OS/.NET、机器、电源计划、存储、身份、
PLC 完整 Profile、发布配方、相机/成像/标定及版本化部署政策生成。
测试签发器只能为实际观察到的目标签署测试证据，不能替换目标或 Runtime 门禁。
生产组合没有内置测试信任根；部署政策声明本身不是性能、备份或供应商合格证据。

Core 包含冻结 Admission、准备实例、算法/配置/Schema、全部结构化结果和 Overlay、
帧身份/来源、采集与执行单调时钟、UTC 记录时间、适用保留义务及固定 PLC payload。
采集无帧失败以版本化的类型化失败原因和 Unknown 固定，不能冒充已执行算法的 Pass/Fail。
新生产编解码格式保留全部图元、Schema 和时间，旧归档格式与旧合同版本保持兼容。

## 事务与生命周期

Admission、Core 和交付事件均由单一 SQLite writer 写入。每次事务内完整验证中央审计链，
校验各周期冻结身份、合法状态转换、Admission/Core 全列投影及其与签名审计 payload 的绑定。
Core 与完整结果/图形/payload 同一事务提交，回执来自数据库重新解码的值。
容量在接纳新周期前预留最长故障/恢复尾部与中央审计控制余量；已有 pending 独立保留，不提前释放。

Runtime 最终许可回调保持非阻塞，避免 SQLite/session lease 与 Runtime 锁反向等待。
只有已确定回滚的 `CommitFenceBusy` 可以在原单调截止时间内重试相同不可变候选；
真实存储失败、超时、已提交或结果未知的操作不能当作普通竞争重试。
Core 回执、实际资源退休和当前许可全部成立后才发送 payload，继而 ResultValid、ResultAck 和 Ack reset。
Core 失败/超时清 Busy、撤 Ready，保留已接受身份并记录故障；没有 Core 的周期不发送普通结果。
逻辑超时后仍占用输入的算法或 provider 必须真实退休，才能进入发布阶段。

Stop 的在途标记、等待审计和终端审计形成同一阻塞边界；尚未开始发送的请求撤销不会污染已确认输出，
但发送结果不确定会封闭后续写入。观察器保留已拒绝周期键，重新 Arm 不会重放旧 Trigger。
自身正常采集进度和审计复核不会伪装成配置变化；真实配置/身份/故障变化仍撤销生产权限。

冷启动先完整读取账本，再决定是否能打开 PLC 通道。Admitted、CoreCommitted、FaultTerminated
及未完成 ACK/恢复的周期均为 pending；只有 AcknowledgementReset 或显式 RecoveryCompleted 解除。
不重算、不补发、不重放旧周期。本票不提供 T44 的实物处置恢复操作。
