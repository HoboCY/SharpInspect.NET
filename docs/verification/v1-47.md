# V1-47：独立治理开机自动武装与 PLC 换方后重武装

关联 GitHub #48；父规格 D14、D16、D22、US-58、US-81；ADR-0086、0098、0110。
开发组合验证已完成；本票不构成真实工位验收。

## 行为与证据

StartupProductionPolicy 默认 ManualArm，PostActivationArmPolicy 默认 ManualRearm。
两项不可变政策各有 Id、Version、内容哈希，独立绑定进部署清单和完整资格指纹。
旧部署构造器及哈希保持原样；显式新构造器使用包含两项政策的新哈希。

自动能力只由当前生产连接所有者创建，一次消耗。开机原因在本次 Runtime 首次健康观察时
考虑一次；PLC 原因必须具有实际成功激活、已完成 ACK/应答清除/请求归零的专用握手。
握手归零后另开一段输入稳定窗口，旧样本不计入；高电平、过大采样间隔会重新计时。
本地激活、登录、相机重连、预览/手动/标定/资格退出没有创建该 PLC 能力的入口。
失败不排队重试，不因随后修复某项门而自动重新尝试。
开机与 PLC 换方争用时，在同一 Runtime 锁内决定归属：已占用的专用换方请求或 PLC 激活预留
会使本次开机起因让开；反过来，尚未结束的自动武装会使 PLC 预留明确返回 Busy。

自动入口使用 Runtime 专属 SystemPermission，不能借用真人身份或 PLC 激活权限。
它复用实际工位事实、完整资格与普通人工武装的最终检查，绑定 owner、RuntimeEpoch、
ControllerEpoch、连接代次、激活引用、维护证据、停产代次、准入代次和耐久配置头。
配置、维护状态、连接、停产或准入授权变化均可撤销尚未完成的能力。
只配置自动 PLC 重武装但缺少专用换方握手或武装状态寄存器块，在配置阶段拒绝。

维护证据是内部可信 reader 边界，默认缺失；缺失或未知时自动武装拒绝。
InProgress 也拒绝人工武装；ManualArmRequired 必须经过实际认证的 ArmProductionCommand，
复核其 schema22 Completed、完整准入报告、用户/Session/CorrelationId，随后完成物理 Ready ACK。
只有绑定相同 station、deployment、journal head 的已验证 ManualMaintenanceArm ReadyConfirmed
才能满足该维护头；新维护头不继承旧确认。内部测试 provider 不是正式部署/升级日志 reader，
不接受通过公共布尔值声明“维护已完成”。正式 reader 与维护生命周期仍由后续票交付；
其缺失不会被本票当作生产合格。

Ready 写成功前仅有 Attempted/Authorized，激活成功本身不会产生 ReadyConfirmed。
实际连接所有者收到 Ready ACK 并通过最终检查时冻结只读 ReadyReceipt，随后持久化并验证。
回执是历史事实：之后停产或授权变化可以撤销当前 Ready，但不能改写旧回执。
ACK 后立即到达的 Trigger 在本次回执审计期间保留，必须等审计确认才进入生产周期。
ACK 后回执或审计失败会清除 Ready，标记审计不可用并要求恢复。

回执绑定确切 Authorized 哈希、RuntimeEpoch、激活、维护头、准入代次、通信代次和时间。
Startup/Manual 通信代次由 Runtime 签名见证，离线读取未额外关联 schema27 通信事件；
endpoint/profile 已绑定完整资格指纹，PLC 原因另外交叉验证 schema31 专用握手与激活。
历史回执解码不产生运行权限。自动 Authorized 另外保存不可变 InputStability：
政策引用、首次/末次/边界样本号、采样数量、持续窗口、最大间隔、样本新鲜度和重置计数。
持续时间以 TimeSpan 的 100 ns 单位编码，独立于机器 Stopwatch 频率。

Schema32 显式可选，复用原中央审计封装；配置缺失、错配或旧库版本变更需要后续显式迁移。
查询验证完整审计链、双向本地记录引用和要求的外部锚定；无可验证回执时返回不可用。
每个尝试单独预留剩余事件及全局审计容量，已结束的其他尝试不能释放它的预留。
无状态块、发送失败和人工确认仍有明确的 PlcStatusUndelivered 处置。
冷启动终结旧 epoch 未完成尝试，补齐状态未确认的处置，不重放旧 Ready 或 PLC 状态。

## PLC 状态块

独立 FC16 只写寄存器块，共 27 个 UInt16，不与生产、心跳、身份、配方换方或结果负载重叠。
这是一次武装尝试的历史状态，当前 Ready 仍由原生产握手输出表达。

| 寄存器偏移 | 含义 |
| --- | --- |
| 0–4 | Valid、Cause、Outcome、Reason、BlockedGate |
| 5–12 | RuntimeEpoch UUID |
| 13–18 | ControllerEpoch、RequestSequence、SelectionCode，各占两个寄存器 |
| 19–26 | AttemptId UUID |

UInt32 使用高字在前；UUID 使用 RFC4122 规范字节顺序。清空时 Valid=false 且其余字段为零。
发送同时校验当前连接所有权及请求/Runtime 代次，发送结果本身也入审计。
