## 范围与边界

通过同一公共 Camera Provider / Camera Device 接口发现和打开明确的 Stable Device Identity，
完整配置后执行一次 Acquire，返回一个规范帧所有权或结构化失败。
Virtual Camera 使用显式版本、输入、种子和可控时间，不依赖墙钟等待来安排场景结果。
帧只支持 Mono8、Mono16（10/12/16 有效位）和 Bgr24，保留规范行布局及独立 Metadata / Provenance。

录制输入采用明确布局和预期内容 hash 的规范原始像素文件；合成输入使用固定算法版本和种子。
该入口不声明支持任意图像容器或自动遍历图像文件夹。

本票提供独立开发模拟器和公共接口验证。Runtime 受权改绑与配置页面由 V1-17 接入，
Runtime 生产采集身份、Busy 硬触发门控、报警和交付路径由 V1-18 及后续票接入。
模拟器通过不构成 Hikrobot / Hardware Provider Qualification、Station Production Acceptance 或 Ready 许可。

## 设计与证据约束

`IFrameBufferLease` 在 Abstractions 定义所有权；Runtime 现有租约实现该接口，
Virtual 依赖 Abstractions 与 Runtime，复用预分配帧池。Runtime 不反向引用 Virtual，
本票不改变算法执行入口既有的具体租约转移语义。

场景限制为每 Provider 最多 4 台设备，每台 1–4 个池槽，冻结图像与规划池总量不超过 512 MiB。
每场景最多 64 个图像、64 次采集、64 个信号，采集脚本按输入顺序耗尽，重开设备不重置游标。
时钟排队上限为 512 个事件；同一时间点按注册顺序执行，同一采集批内多个当前帧明确拒绝。
单次推进最多执行 4096 个回调，错误返回稳定原因。
当前模拟器先注册采集信号、后注册该次截止事件，因此恰好在截止点到达的唯一合法帧先被处理。
这是明确的模拟器排序规则，不能替代 V1-18 的 Runtime 生产超时政策。

Virtual Time 安排配置完成、帧到达及采集截止点。共用帧池的真实 `Stopwatch` 复制预算保持启用，
这类资源失败与脚本预期失败分开计数，不能作为确定性场景的成功证据。
相同输入要求相同帧与可观察健康、时间、结果；租约随机身份与真实 CPU 耗时不属于确定性记录。
