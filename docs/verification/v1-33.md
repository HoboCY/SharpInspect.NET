## 行为与适用边界

Preview 使用独立 session/frame identity，显式命令在 Runtime 准入后清 Ready 并 Disarm。
帧、显示与设备读取均有容量限制；连续预览不进入生产算法、Inspection ID、结果持久化或 PLC 握手。
冻结与保存是分离的命令。保存复用 Draft 的验证、EditRecipeDraft 授权和精确 revision/hash CAS，
保留生产触发模式、超时、触发延迟及其他 Draft 内容。保存已经提交后，额外 Preview 审计失败不能改称保存回滚。

退出与权限丢失必须停止连续流并完整恢复、读回原 Active 相机配置；无原 Active 时验证安全关闭，
终态为 `NoActiveBaselineClosed`。恢复成功仍保持 Disarmed。恢复失败要求实际锁存的
`PreviewRecoveryRequired` / `Runtime.Preview` 告警及 `BlockNewTriggers`。
重启从内部已验证账本读取原 admission 和依赖，原 Start 命令的责任一直保持到会话终结。

Local Stop 用例在实际 Apply 屏障处注入停止，验证后续 Preview Start 被阻止且设备安全关闭；
不把已经发生的 Apply 记为零 I/O。Active 恢复使用内部友元夹具；公开示例以无 Active 的
安全关闭验证整条交互流程。真实相机、PLC、生产算法、正式资格 Profile
和真实工位验收均未执行，也不由本票开发夹具授予。

本票的连续预览设备实现为可选的 `ICameraPreviewDevice` 能力，Virtual 提供公开演示。
缺少该能力的适配器返回 `PreviewCapabilityUnavailable` 并安全退出；本票不宣称 Hikrobot 或真实设备已支持该连续预览接口。

默认 RunPreview 不要求 Step-Up。显式更严的策略仍由 Runtime 校验；Draft 保存使用
`SavePreviewToDraftCommand.CreateDraftSaveStepUpBinding()`，绑定 EditRecipeDraft、同一 command correlation、
DraftId 与 SaveRecipeDraft。命令的 `AuthorizationTarget` 则标识 Preview 历史中的保存意图。
当前 WPF Preview 页面不采集重新认证凭据；要求额外认证时会拒绝操作，公开 Runtime 调用方可按上述绑定提供有效 grant。
用于资格检查的独占 `CameraAcquisitionService` / `CameraRecoveryService` 不提供 Preview 所有权交接，
同时注册时入口保持 `PreviewCameraOwnerConflict`。
