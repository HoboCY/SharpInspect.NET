## 交付边界

Trace Storage Policy 是独立部署治理。显式版本包含 11 类保留规则及起算事件、磁盘储备绝对字节与百分比、
每条 Required Route 精确契约与数量/字节/年龄限额、图像积压限额、Evidence Stage 与 Trace Commit 截止时间、
scrubber/checkpoint 周期和 I/O/时间预算、WAL 上限及审批依据/版本/理由。编辑器没有隐含生产数值。

发布由 authenticated Human 的 `ManageProductionPolicy` 和强制一次性 Step-Up 授权。授权目标包含候选政策
hash、预期已发布版本和操作理由；writer 在事务内重新检查身份及权限，按版本 CAS 写入不可变政策记录。
`ApprovalReference`/`ApprovalVersion` 是审批依据编号与版本元数据；本次人类发布者通过权限和 Step-Up
批准完整 `Policy.ContentHash`，publication 记录该审批人的身份、会话、授权版本、grant 和时间。
源记录与规则快照始终引用精确版本，后来的较短政策不能修改旧快照。发布事件进入生产准入的 durable-head
绑定，旧准入输入不能跨政策变化继续使用。

本票持久化的是政策与冻结保留规则。真实 Trigger 接受时的 per-Run 原子锁存和实际证据义务由后续周期消费，
本票不创建 Inspection ID、虚构证据或起算时间。纯保留义务值及延长/Hold 谱系不能签发删除许可，也不提供
缩短既有义务的普通政策发布路径。核心事实、不可变审计、Recipe 历史和标定治理证据不在自动删除类别中。
纯义务 hash 同时绑定 artifact、冻结快照、publication 和该快照内的规则；连续延长绑定上一有效期限，
Hold release 不得早于 placement。后续持久化消费者仍须验证当前谱系和活动 Hold。

预检从实际本地卷和 writer 已验证的 SQLite PRAGMA 观察中给出储备/WAL 等结果。磁盘储备使用
`max(absoluteBytes, ceil(totalBytes * percent / 100))`；缺失容量或 WAL 元数据不可读保留为未知，不当作零。
当前可用空间不足影响准入，不禁止发布结构完整且物理可行的政策。未实现的 checkpoint/scrubber 政策执行、
图像与路由积压核对、证据 reconciliation、其他部署政策和生产周期继续保持 NotImplemented。
当前 `DeploymentScope` 是显式可信部署输入，不永久锁进账本容量配置。路由清单变化后仍可启动及读取旧政策，
预检显示 RouteInventory Mismatch，重新批准匹配当前清单的新政策；历史政策按其冻结内容验证。
