## 行为和配置边界

`ProductionStoreOptions.EvidenceReconciliation` 是独立可选能力，显式启用 schema 38。
旧库必须经 Startup Maintenance 完成 35／36／37→38；省略选项保持原功能组合。
完整图片 profile 可以独立启用，不会凭空引入 Outbox 或手工恢复功能。
迁移绑定原配置、源库、备份、应用二进制及新的核对配置；原行、rowid、NULL、哈希与历史字节保留。

图片 stage、final、隔离根必须是受控本地固定 NTFS 目录，禁止重解析点、同步根、重叠根和多硬链接文件。
stage／final 各自的隔离根与来源同卷。移动前持有文件及祖先目录保护，核验文件身份、长度和内容哈希。
先持久化隔离意图，再从同一文件句柄执行不覆盖的重命名，最后追加完成事实。
重启可从来源仍在或目标已在两个窗口恢复；两处同时存在、两处都缺失或身份变化均拒绝确认。
隔离记录没有 Inspection／Manifest／Work／Delivery 身份，不能被当成生产证据。

当前进程启动完成前，Ready 保持关闭，图片 worker 和外部发送等待统一屏障。
旧 Outbox 活动尝试先耐久记录 UnknownOutcome，再确认本地恢复完成；数据库忙或超时不能被吞掉后放行。
启动完成事务独立检查每个所需来源及最新生命周期，拒绝尚未终结的旧发送尝试。
缺失历史处理器按历史契约形成耐久阻塞；核对不产生外部接受事实、不重新发布 PLC 结果。

合法 Pending 保留原工作身份进入后续处理。已有绑定 final 而数据库仍 Pending 时，
完整 decode／canonical pixel hash 校验后确认 Succeeded；缺 stage、但绑定 final 完整的中断窗口可恢复。
若 stage 仍在但已损坏，即使 final 有效也记录完整性故障。无绑定 final 只能隔离，
不能凭文件名或像素相同补造 Core／manifest／成功事实。
故障记录不可变且保持锁存，补回文件或稍后核对成功不会擦除故障。

历史巡检按来源位置冻结上界，每页原子追加观察和 checkpoint；暂停、取消及冷重启保持原 RunId 和进度。
每轮限制条目、时长与文件读取字节，活动图片单列 Deferred，不冒称已验证。
图片与 Outbox 每轮交替，即使某轮零提交让出也不饿死另一类历史。
文件读取、PNG 解码和完整审计验证在写协调器外进行；只在最终提交中重查来源和覆盖。
同一只读 SQLite 连接的 data_version witness、审计尾与来源版本共同保护验证到提交的窗口；
连接槽直到物理操作结束才释放，不能用取消制造额外并发。
已有的部署 Trace Storage Policy 的 Scrubber 预算必须与此配置完全一致；
新增配置与 worker 执行 profile 纳入部署指纹。

`IEvidenceReconciliationQuery` 和 WPF 页面只提供分页查询，显示最近启动、历史巡检、
已验证／延后计数、隔离待办及锁存故障。离页、锁屏、注销或销毁时清除当前显示，
忽略迟到响应；页面不提供解除故障、修改历史或重新交付入口。
预检显示最近持久化启动结果；实际 Ready 另外要求当前 RuntimeEpoch 的启动屏障通过。
