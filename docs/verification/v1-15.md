## 数据与编辑契约

`IRecipeDraftEditor` 是受限的草稿目录、作者默认值、验证、保存和有界历史接口。
编辑器没有 Runtime 命令、设备、数据库或任意服务解析权限。
`IRecipeDraftHistoryQuery` 是独立只读入口，不初始化 writer，不要求 Factory 注册。

草稿绑定一个原子算法，以及精确 Configuration Schema、Result Schema 和 Overlay Contract 身份。
原配置 Schema 的字段、约束、作者默认值、帮助文本和完整 Snapshot 随修订保存；重开不使用当前默认值。
五类标量保持类型：Int64 不经 double，Float64 必须有限；字段与单位必须精确匹配，未知字段整体拒绝。
可选 false、空 String 和未设置分别解释。每个配置值有唯一 Explicit 或 AuthoringDefault 来源；
后者必须与该份原 Schema 的默认值相同。缺少必填参数不能靠保存时隐式补默认得到有效配置。

配置字段的可选 `HelpText` 以 literal text 显示，有严格 UTF-8 大小限制。
有帮助字段时，Schema hash 追加版本化帮助元数据；未声明帮助的旧 Schema hash 保持原值。
该作者元数据不属于结果测量字段，结果 Schema 对其明确拒绝，避免历史结果序列化静默丢失。

`RequestedCameraConfiguration` 只表达 ADR-0033 的公共九类过程设置与单位；不是已应用/读回的 Effective 证据。
草稿声明逻辑相机角色、有限执行期限和类型化资产/政策需求，不保存设备地址、凭据、触发线或存储路径。
算法参数中的 String 是算法声明的字面值，不提供文件、URI、脚本、XAML 或服务加载能力。
执行期限必须匹配显式部署 AlgorithmExecutionPolicy 的身份/hash/范围；其他依赖保存为要求，满足检查为 NotRun。

## 校验、身份与持久化

保存自身重新执行结构和实际注册 Factory 的语义验证，外部 Validate 的结果不能充当可提交凭证。
Draft 验证与算法准备对同一个物理 Factory 使用同一串行 gate，验证不会继续 Create、WarmUp 或 Execute。
异常返回稳定原因，不把异常文本、模型路径或凭据输出给编辑器。
验证在结构检查和编码前最多接纳 16 个任务，最多两个任务进入语义验证；保存入口另限四个逻辑请求。
逻辑验证超时后，尚未返回的 Factory 工作继续占用验证容量及该 Factory 的串行 gate，直到实际退出。
因此四个保存名额不代表所有遗留物理任务的总数；两层容量分别解释。

新增独立 `EditRecipeDraft` Permission；角色只提供赋值集合，实际权限从已验证的本地人员状态读取。
原有 `AuthorizationPolicy.Development` 的角色集合与内容 hash 保持不变；草稿消费者使用显式赋予
Technician/Administrator 草稿权限、另有 Id/Version 的新开发策略，不隐式改动旧库绑定策略。
保存事务内重新核对会话、人员、授权修订、所需 Step-Up 与取消；按钮状态和调用方 ID 不授予权限。
每次保存绑定 OperationId、DraftId、ExpectedRevision 和 ExpectedRevisionContentHash。
幂等重试不能再追加贡献；并发冲突不能覆盖历史或生成分支。

三个身份分别解释：Configuration Content Hash 绑定规范参数；草稿 ContentHash 绑定内容及来源；
RevisionContentHash 另绑定前序、修订身份、真实作者/会话/授权修订、原因和审计时间。
CAS 比较修订号和完整修订 hash，不只比较内容 hash，因此 A→B→A 不能让旧客户端覆盖新修订。

草稿能力只从新空库创建 schema 9；schema 1/2/7/8 保持各自路径，旧库开启新选项时要求受治理迁移。
每条修订、前序与签名审计经同一个单写事务追加。只读查询按固定 ThroughPosition 分页，
核验完整链和页面外修订，载荷、索引或前序篡改均不可隐藏在筛选之外。
单条规范载荷最多 2 MiB、单页 4 MiB、总量 256 MiB、10000 条修订，显式较低限制同样生效。
这些容量与共享审计核验预算共同限制实际可保存数量；超限整体拒绝。
