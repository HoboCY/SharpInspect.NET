# V1-26 平面单应映射候选

关联工单：[Issue #27](https://github.com/HoboCY/SharpInspect.NET/issues/27)。

## 输入与权威边界

可选 `SharpInspect.NET.Calibration.OpenCvSharp` 包实现 `PlanarHomographyProcedure`。
会话前冻结的靶标设计包含 DICT_4X4_50 Marker ID、各 Marker 解码方向下的四个物理角点、
靶标定义 ID 和平面坐标系 ID。物理坐标单位为毫米；原始图像为 ROI 内局部像素中心，
左上像素中心是 `(0,0)`，X 向右、Y 向下。

这些物理角点是靶标设计参数，不是人工替换的检测坐标。检测点来自实际源图像；
Marker ID 与解码后的 corner index 共同标识对应关系，不能按图像 X/Y 重新排序。
OpenCV 4.11 在解码后按 Marker rotation 归一化角点顺序，见
[官方 ArUco 检测源码](https://raw.githubusercontent.com/opencv/opencv/4.11.0/modules/objdetect/src/aruco/aruco_detector.cpp)。
靶标制作精度、安装位置和平整度仍需要独立物理验证。

输入逐项绑定逻辑相机角色和完整 Effective Camera Configuration。适用成像修订沿既有
`ExpectedImagingSetup → CalibrationSessionHeader → CalibrationCandidateEvidence` 权威链绑定；
裸系数不具有当前有效性、发布或激活权限。系数中保留完整规范输入与输入内容哈希，
从而同时绑定坐标、靶标、配置和像素域。

像素域必须显式指定 `RawRoiPixelCentersCorrectionDeclaredNotRequired`。
Unknown 和未知枚举拒绝；`ExactIntrinsicCorrectionRequired` 返回
`PlanarIntrinsicCorrectionUnsupported`，不会悄悄取消校正需求或调用 UndistortPoints。
本版本未交付可持久验证的精确内参依赖及复合校正映射，因此需要这项能力的项目继续拒绝准入。
原始域候选能否满足某个工位的要求由独立验收政策决定。

## 观测与数学边界

每个候选只接受恰好一个未排除观测。不同拍摄姿态可能具有不同的 H，不能合并、择优或
使用 RANSAC 删除残差较大的点。多个源图像可以留存，但必须在计算前按已有整帧排除规则
记录可见问题与理由；重新提取产生新的观测。

提取从同一次有效行像素副本计算 SHA-256 和运行检测。独立进程私有 HMAC receipt
绑定过程、完整输入、会话／帧／来源、像素和有序 feature 内容哈希；计算只验证首次提取
凭据，不重新检测或容差比较。空图及未知／重复标记保留诊断；凭据不赋予重启后继续计算权限。

所有实际参与点用于非稳健估计，保留两方向矩阵、逐点原始图像／物理坐标与双向残差、
秩检查、闭合误差、缺失 Marker 和覆盖。有效区域是实际观测的图像／物理凸包，
不扩大到全 ROI 或完整设计靶面。映射在对应源凸包内返回有限值，区域外和齐次分母不安全时拒绝。
局部尺度给出 image→plane 的解析 2×2 Jacobian、两个方向伸缩量和面积尺度；没有全图统一 mm/pixel。

两个凸包分别限制该方向的输入，不再次限制输出是否落在对侧凸包。带残差拟合时两者经 H
变换后未必完全重合；因此两次带区域检查的 API 不能保证在所有边界点串联成功。
矩阵的代数正逆闭合独立验证，不通过扩大凸包或删去残差来实现。

DLT 将两侧坐标分别居中并缩放，第八大奇异值／最大奇异值低于 `1e-5` 时拒绝数值退化；
四点情形检查 8×9 矩阵的第八个奇异值。矩阵按最大绝对元素与固定符号规范化，不要求 h33 非零。
行列式消减与齐次分母使用 `64 × 2.2204460492503131e-16` 相对数值保护，
局部最小方向尺度通过面积尺度／最大方向尺度取得，避免相近特征值相减造成的精度损失。
这些固定值是版本化实现的数值保护，不是项目残差、覆盖或生产验收门限。

核心 Abstractions／Runtime／WPF 不增加 OpenCV 数学模型依赖，Schema 仍为 14；
复用既有版本化计算证据与提取凭据存储。候选不自动发布或切换 Profile。
