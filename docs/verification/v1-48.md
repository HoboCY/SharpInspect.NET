关联 GitHub #49；父规格 D16、US-53/56/57/65；ADR-0095、0096、0097、0105。
本票实现、独立复核和开发验证完成；完整回归、包消费者及旧版二进制兼容性均通过。

## 行为

未用于发布的 Draft 可被永久放弃；精确 Released Recipe 可被永久退休。
两项操作都要求独立权限、实际有效且绑定目标与原因的新鲜 Step-Up，
最终 SQLite 写事务重新检查用户、会话、权限修订、目标版本和 Active 比较条件。
生命周期事实与授权、命令审计在同一事务中追加，不删除内容、贡献历史或旧发布事实。

退休 Active 时，由 Runtime 持有专用预留并停止新生产准入。
已接受周期继续实际算法执行、结果提交、ResultAck 和确认复位；
只有周期真正退出且原连接所有者确认 Ready=false 后才能提交退休。
取消先于提交认领则不产生退休事实；认领先于取消则等待写入方的明确结果。
退休提交后清除 Active 并保持未武装。插件清理超时保留真实任务并要求恢复，
不会撤销已提交退休，也不会把超时当作资源已经释放。

Active 查询先选择最新有效激活事实，再应用明确的清除屏障，禁止自动选择更早版本。
回退通过普通激活执行，旧版本必须仍 Available，并通过当前算法、相机、标定、
结果契约和生产资格检查。PLC 结果契约必须具有该精确发布版的已发布绑定；
仅能在内存重新计算出兼容绑定不足以获得激活权限。

Selection Map 不会因退休而改写；退休记录保存已存在各版本映射的受影响代码。
新映射不得引用退休版，旧映射的 PLC 请求明确返回 RecipeRetired。
被放弃或退休的内容不能直接用于手动检测。

从保留历史派生内容必须新建 Draft 身份，保留精确来源生命周期、修订和贡献关系，
由普通 Draft Save 执行当前验证。显式配置迁移同时保留生命周期和迁移两条来源关系。
导出声明真实 Draft/Released/Abandoned/Retired 状态，写入方再次比较冻结状态；
准备导出后发生退休或放弃时拒绝过期导出。导入仅创建新 Draft，外部状态作为来源信息，
不携带本地发布、Active 或生命周期操作权限。

Schema33 为显式可选配置，要求 Draft、身份和审计组件；旧库不得自动升级。
生命周期记录与中央签名审计双向绑定，查询同时校验跨账本业务顺序。
每条记录按精确审计序号解析授权，不随记录数量重复扫描完整身份事件账本。
未启用功能时保持原格式、政策默认哈希和公共构造器。
