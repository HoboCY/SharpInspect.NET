# V1-23 成像修订与配方标定需求

关联工单：[Issue #24](https://github.com/HoboCY/SharpInspect.NET/issues/24)。

## 交付边界

Recipe 只保存 vendor-neutral `CalibrationRequirement`：逻辑相机角色、种类、用途、
精确系数格式契约和验收政策契约。系数保存在独立不可变的 `CalibrationProfileContent`；
Recipe 不携带 Profile ID、设备序列号、成像修订、文件路径或系数。

本票的 Profile catalog 是显式隔离夹具，候选与历史标签均不代表本地发布。
精确兼容命中只产生 `DevelopmentOnly` 诊断；`ProductionAuthority`、`CanActivate` 始终为 false。
兼容夹具也不能允许依赖该标定的调试；只有无标定需求时，此标定调试门才可通过。
真实候选计算、政策验收、发布、有效性复验与生产激活仍由后续工单提供。
没有标定需求时返回 `CalibrationNotRequired`，不产生默认系数；这只满足标定依赖的调试检查，
不替代相机、非生产会话和普通授权门槛。

## 数据与查询规则

- 每个草稿最多八条 typed 标定需求；角色必须与该单相机 Recipe 相同，重复角色／种类／用途被拒绝。
- 系数格式和验收政策均使用 ID／版本／内容哈希；仅同为 Intrinsic 不能证明不同畸变模型兼容。
- 系数字节有 64 KiB 上限，构造和返回均防御复制。框架计算内容哈希，格式定义单位与坐标约定。
- Profile 内容哈希覆盖完整需求、设备、成像修订、Requested／Effective 几何、系数及其格式、
  程序来源、证据摘要、创建人和时间；修改内容形成不同身份。
- 选择使用精确 `(ProfileId, Version, ContentHash)`，没有 latest、文件名、唯一兼容项或自动回退选择。
- 解析器读取授权的当前 Camera Setup 和 Imaging Setup；先核对真实绑定，再比较角色、种类、用途、
  系数格式、政策、设备、修订和 Requested／Effective ROI、尺寸、规范像素格式与有效位。
- 标定需求未满足时不允许依赖该标定的调试，生产标定门也保持拒绝；旧修订 Profile 不能绕过新物理修订。

## 成像登记与存储边界

`ImagingSetupChangeRequest` 携带实际 Camera Binding 和 Imaging Setup 的预期修订／哈希，
完整物理定义与变更原因共同形成授权目标。登记要求当前个人会话、`ManageCameraBindings` Permission
和绑定该操作的再次身份验证；与相机绑定、调试、重连、网络维护共享操作互斥门。
持久化事务再次检查身份授权修订、绑定和成像修订，写入命令、个人归属审计和不可变修订。

Schema 13 为显式成像账本扩展，要求 Camera Setup、Local Identity 和签名审计；
Camera Recovery、Camera Network 可独立选择。旧格式不自动升级，缺少扩展配置保持拒绝。
默认容量为 10,000 条修订、每条 128 KiB、总计 256 MiB；配置可以收紧，不能超过硬上限。
查询保留固定历史上界，最多每页 256 条。完整性检查覆盖配置、连续位置、前序、内容哈希和授权关联。
成像读取也验证已启用的恢复与网络账本，保持共同签名历史的完整验证边界。

物理事实由操作者明确声明，软件不会自动发现所有镜头或支架移动。登记产生新修订后，
以前修订对应的标定不能继续匹配；此过程不创建或发布新的标定系数。

## 草稿兼容

无 typed 标定需求时仍输出原 V1／V2 规范 JSON，保留历史 hash 路径。
非空需求使用严格 V3，其中 `CameraProviderExtension` 必须为对象或显式 null，
`CalibrationRequirements` 必须完整；携带站点 Profile 或系数的多余字段被拒绝。

旧 `RecipeAssetKind.Calibration` 和 `RecipePolicyKind.CalibrationAcceptance` 历史仍可读取，
但新保存会要求显式转换，因为旧条目缺乏种类／用途／系数契约，不能安全猜测，也不能形成两个政策来源。
通用编辑器提供 typed 行，并保留旧条目供用户查看和明确删除转换。
