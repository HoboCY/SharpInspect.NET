# V1-27 项目标定政策、开发 Profile 发布与有效性

关联工单：[Issue #28](https://github.com/HoboCY/SharpInspect.NET/issues/28)。

## 范围与资格

通过 `ICalibrationGovernanceRuntime` 发布不可变的项目政策、评估保留候选、发布开发
Profile 和追加 Physical Calibration Verification；通过 `ICalibrationGovernanceQuery`
按精确引用读取历史和当前有效性。四种操作都有独立命令目标、授权、一次性 Step-Up
和同一 SQLite 事务中的命令、身份、治理审计记录。

T24–T26 保留证据的开发属性不变。政策通过表示证据满足所选政策，可创建不可变的开发
Profile；`DevelopmentOnly=true`、`ProductionAuthority=false`、`CanActivate=false`。
没有任何 API 将这些记录转换成真实工位资格。后续 Recipe Activation 和生产执行必须
继续消费全部准入门，不能把政策评估通过等同于 Ready。

当前 Runtime 尚无生产 Trigger 接收与已接受 Inspection Run 的完整执行路径。
本票提供精确 Profile / Imaging Setup 解析、有效性投影及不可变运行绑定数据合同，
不声称已经验证实际生产周期快照、到期 Alarm Instance 或 PLC Trigger 阻断。
这些路径保持 `ProductionCycleUnavailable` 等既有拒绝条件。

## 冻结政策与证据

政策明确六类门：样本数、覆盖、姿态、多图残差、逐点残差、异常观测。
Required 门不能为空；允许不适用的门必须带明示理由。门的类型、键、单位、比较方向、
阈值、适用性和理由均进入内容哈希。样本数要求整数 1–64，覆盖为 0–1，排除数为整数
0–64；框架没有通用生产精度、固定复验月份或手工覆盖失败的入口。

会话的 Calibration Requirement 已预承诺政策的 ID、版本和内容哈希。政策必须在权威
评估前持久化；发布新政策版本不重新解释旧候选、旧 Profile 或旧有效期。Profile 同时
绑定候选、政策评估、过程合同、系数、设备、逻辑角色、Imaging Setup Revision 和实际
请求/有效图像几何。发布使用精确前驱版本比较，旧版本保持只读。

Evaluate 和 Publish 均重读全部保留源图像（包括已排除帧），验证长度和 SHA-256。
只有 SQL manifest 相符不足以发布。所有参与观测还必须符合首次冻结的选择政策、
提取凭据和计算证据合同；缺失门或缺失指标产生明确失败。

## 实物复验与有效期

项目政策显式指定独立参考、复验过程、证据合同、物理指标及有效间隔。
主机必须注册 exact procedure/evidence contract 的 verifier；没有默认 verifier。
复验过程只能读取 Profile、独立参考、执行时间和证据，不能读取调用者上传指标。
Runtime 在过程外比较重算值和上传值；缺失过程、格式错误或结果不一致均不产生有效期。

一次追加操作保留原始证据及门结果，系数不变。重复键使用证据内容哈希与独立参考内容
哈希，修改记录时间、参考名称或版本不能借同一份证据续期。最新失败覆盖历史通过；
`now >= ValidUntilUtc` 即 Expired，返回 `CalibrationVerificationOverdue`。
已发布 Profile 始终使用其精确政策版本的间隔。

复验过程执行有超时及并发上限。不响应取消的过程在真正结束前继续占用运行槽，不能
因超时释放而堆积后台调用。重启不重新调用外部 verifier：已签名事务证明写入时执行了
重算及一致性检查，重放核验精确引用、证据哈希、指标、门结果和有效期。

合成消费端示例的 12 小时、0.5 mm 等值仅是显式开发政策输入。独立真值使用 T26 冻结
渲染矩阵在未参与求解的位置生成检查点，不能证明真实量具、证书、安装或工位精度。

## 存储与兼容

显式 `CalibrationGovernanceStoreOptions` 启用 schema 15，依赖原 calibration-session
配置。旧 schema 14 不自动迁移；未配置治理的主机不能打开 schema 15 作为可写旧库。
旧政策 Development 哈希及 schema 14 的候选、凭据和字节格式保持不变。

schema 15 增加有容量限制的追加账本及新的中央审计 envelope。记录逐项绑定命令事实和
身份授权的审计哈希。事务提交前检查完整 AuthorizationTarget、命令引用、actor、session、
authorization revision 与一次捕获的治理时间；查询、启动和后台审计都验证跨记录语义。
治理时间和对应身份授权时间精确一致，没有隐藏的五分钟允许窗口。
