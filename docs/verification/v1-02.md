## 实现边界

Runtime 只持有内部类型化审计写入能力；UI 只持有 `ICommandTraceQuery`。
Accepted 的前提是 Outcome 事务成功；其后完成或失败另行追加，同一 Attempt 的上下文不变。
记录系统主体固定为 `SharpInspect.Runtime`，本票尚无已认证 Human Principal。
每次调用生成独立 Attempt ID；相同 Correlation ID 的后续调用保留拒绝事实，不重新接纳命令。
无效来源枚举、超过 256 字符的声称主体被拒绝，并以空的有效来源/主体归因记录；不把畸形输入当作已知身份。
Runtime 从不通过历史成功记录恢复 Ready 或武装状态；重开查询从数据库事实重新形成结果页。

无存储或写入失败时，当前原本未配置、非 Ready 的宿主拒绝需要审计的转换。
完整生产停止在途周期与故障中止语义属于 V1-45；本票不以本地禁用状态冒充 PLC 停产完成。
关闭请求先阻止新工作，再等待同一命令锁：已经进入提交的本地禁用终态先结算；
尚未开始终态事务的 Pending 则追加 `RuntimeStopped` 失败事实。关闭不改写已经提交的终态。

单写队列默认最多 64 个等待请求（配置范围 1–256）；Runtime 最多准入 64 个命令。队列等待与事务共享单调截止时间。
SQLite 的原生 busy timeout 和进度回调使用剩余时限，规避驱动按整秒自动重试；不把它宣称为
可抢占磁盘 I/O 或操作系统调度的硬实时保证。只读查询最多 4 个同时运行、64 个运行或等待，
文件与注册表检查也在线程池执行，避免阻塞 WPF Dispatcher。
自动 WAL checkpoint 禁用；单写 worker 在交付结果后、队列为空且距上次维护至少 5 秒时尝试
100ms 时限的 PASSIVE checkpoint。64MiB WAL 上限触发稳定故障原因；本票不执行 TRUNCATE/VACUUM 或无授权清理。

路径检查包含绝对本地路径、固定 NTFS、祖先及 DB/WAL/SHM/lease 的 reparse、ADS/路径别名，
OneDrive 等已知环境根以及 HKCU/HKLM SyncRootManager（含 SID 命名的 UserSyncRoots）。
读取注册根失败会拒绝。未注册的第三方同步程序及其他 Windows 云文件实现需要部署侧确认，
此开发运行不能证明任意目录从未被同步；尚未完成的部署政策和资格继续阻止 Ready。

真实 WPF smoke 曾发现 `Run.Text` 默认双向绑定只读属性导致窗口启动失败，已显式改为 OneWay，
并在同一 smoke 流程复验通过。查询资源上限加入后也实际出现过并行测试触及容量的失败；
最终采用与命令边界一致的 64 项总准入上限，4 个执行槽，完整并发测试通过。失败没有被计为通过。
独立审查发现的提交后维护异常已通过 F07 先复现响应超时，再验证修复后返回已提交结果。
P03 也先在旧消费产物中复现大写环境变量漏检，再验证新产物拒绝访问；环境改动仅发生在子进程。

测试中的 `ProbeAuditWriter` 仅隔离 Runtime 的并发/提交边界，不提供生产注册入口，
不计入 SQLite、断电耐久性、身份认证或 Framework Qualification 证据。
