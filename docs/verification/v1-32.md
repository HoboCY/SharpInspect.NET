## 实现边界

`ActivateRecipeCommand` 绑定准确 Released Recipe、发布记录、预期 Active、标定选择与变更原因。
本地操作者须持有 `ActivateRecipe` 权限；默认不额外要求 Step-Up，项目收紧的授权政策仍被执行。
激活独占预约先清 Ready、Disarm，检查检测、交付、恢复、维护、工程会话及相机配置互斥。
Provider 与算法准备期间不持有 Runtime 命令门；本地 Stop 立即标记取消，第三方取消回调不阻塞
Stop。最终提交声明与 Stop 在同一 Runtime 锁上排序，释放或过期预约不能安装资源。
每次候选相机物理阶段开始前在该锁内取得独立声明；Stop 之后不能取得下一阶段声明。
首个声明被拒绝时保留原相机投影与设备所有权，只有真实关闭、转交或恢复才能退休句柄。
授权回调采用非阻塞 Runtime 锁检查，避免会话锁与 Runtime 投影互相等待。

SQLite schema 18 显式启用激活账本，依赖相机设置、草稿、发布、PLC 结果契约、本地身份和
完整性审计。旧 schema 不自动升级。物理操作前先持久化不可变 Admitted，保存准确候选、
原 Active 和冻结快照、操作者、会话、授权版本与意图。准备完成后，在写事务中重查
Active CAS、授权、相机绑定、当前契约及适用标定；成功终态、Active 选择和审计共同提交。
持久化成功后才交换算法与相机资源，资源退休失败会阻塞后续运行，不重写已提交的 Active。

失败或取消保留原持久 Active。改动过共享硬件时，按旧成功快照完整 close/open/apply/read-back，
确认完整 Effective 配置与健康状态。相机角色变化时先退休旧角色，候选失败则先安全关闭候选，
再恢复旧角色。未退休的超时 Provider 调用阻止再次 open。无旧 Active 时记录实际安全关闭，
不称为恢复。恢复失败锁存配置互斥；成功恢复也不会自动武装。

冷启动有独立、受跟踪的恢复任务，等待基础存储初始化，但不成为基础初始化的一部分，也不
预约普通激活通道。启动窗口保持配置互斥。它通过内部 SQLite 权威读取器读取未终结 admission，
公开可替换的查询能力不能证明恢复已完成。实际相机恢复和终态写入均成功，并重新确认历史后，
才解除启动互斥。恢复失败保留持久 pending；持久 Active 只作为历史投影，不伪造存活的算法实例。
Shutdown 先等待激活和启动恢复，再处置相机；超时保留所有权并报告关停未完成。
冷恢复终态复用原 admission 的命令上下文，保留原 Runtime epoch、来源、操作者、会话和
Step-Up 历史关联。每条激活记录都要求完整命令与身份审计引用，离线篡改授权哈希导致冷读拒绝。

标定逐项检查准确 Profile、兼容要求与系数契约、当前政策、通过的评估、最新物理验证、严格
有效期 `now < ValidUntil`、设备身份、成像物理修订、Requested 和 Effective 几何。T27 的
DevelopmentOnly Profile 始终不能提供生产激活权威。无标定要求才可记录 NotApplicable。

Part Identity 使用显式 None / Optional / Required 声明。历史配方没有该字段时表示未声明，
不会自动视为 None。新字段使用草稿格式 5 和独立哈希后缀；历史格式 1–4 的字节与哈希不变。
算法迁移、普通编辑及发布来源追踪保留该声明。

## 尚未交付的准入能力

ADR-0096 仅允许 Performance Qualification 和 Station Production Acceptance 在激活阶段
尚未完成；它不免除其余必需依赖。当前公开组合仍缺框架与 Provider 资格权威、生产采集布局、
PLC 部署握手、Evidence/Core 准入、部署政策和生产周期，实际命令会记录缺失检查并拒绝。
当前也不能将未实现的资产、模型、扩展或 Optional/Required Part Identity 绑定标成通过。

内部友元夹具仅替代尚未交付的 A12–A18 权威，用于检验真实授权、SQLite、算法准备和虚拟
相机的协调过程。记录明确带有 `InternalContractFixture`，普通当前 Active 查询不会把它投影
为生产 Active。没有公开 Options、命令或 DI 开关能启用这个夹具。几何测试、开发消费或内部
成功夹具均不构成真实工位资格或生产准入。
